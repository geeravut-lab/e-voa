> · `src/lib/notify/messages.ts`, `events.ts`, `src/lib/stock/notices.ts`, `src/lib/telepharmacy/notices.ts`, `src/lib/ekyc/notices.ts` (ตัวสร้างข้อความ)
> · `src/lib/notify/deliver.ts` (`pushToLine` — การส่งจริง) · `src/lib/notify/server.ts` (`lineDeps.push`) · `src/lib/notify/notify.test.ts` (เทสการ์ด)
> ไฟล์นี้ว่าด้วย **หน้าตาและโครงของการ์ด** เท่านั้น — คิว โควตา retry และ dedupe อยู่ใน `docs/LINE-NOTIFICATIONS-KNOWLEDGE.md`

## 1. ปัญหาที่แก้

การ์ด LINE ไปโผล่บนมือถือของคนที่อาจไม่เปิดแอปทั้งวัน (ดูจากหน้าจอล็อกหรือรายการแชต) จึงต้อง

1. **เข้าใจได้ในตัวเอง** — ตอบได้ว่า _อะไรเกิดขึ้น / กับอะไร / เมื่อไร_ โดยไม่ต้องกดเข้าแอป
2. **ไม่เปิดเผยข้อมูลอ่อนไหว** — ข้อความสุขภาพ/การปรึกษา/ยา ไม่ขึ้นบนหน้าจอล็อก
3. **ไม่ถูก LINE ปฏิเสธ** — LINE ปฏิเสธทั้งข้อความถ้าข้อความใดยาวเกินขีด
4. **ไม่มีสองแหล่งความจริง** — กล่องแจ้งเตือนในแอป คิว LINE และการ์ดใช้ข้อความชุดเดียวกัน
5. กดแล้วเปิดหน้าที่เกี่ยวข้องได้ทันที (และไม่ต้องล็อกอินใหม่)

## 2. สรุปสั้น

1. **ข้อความเก็บเป็น plain text ชุดเดียว**: บรรทัดสรุป + บรรทัด `ป้าย: ค่า` (`noticeBody`) — ไม่มีคอลัมน์ใหม่ ไม่มี JSON เฉพาะ LINE; การ์ดสร้างจากข้อความนี้ตอนส่ง (`parseNoticeBody`)
2. **การ์ดเป็น Flex bubble ใบเดียวต่อข้อความ**: หัวเรื่อง (ตัวหนา สีทีลเข้ม) → บรรทัดรายละเอียด (≤ 8 บรรทัด) → ปุ่มหลักสีโคราล "เปิดแอป"
3. **`altText` มีรายละเอียดครบ** (หัวเรื่อง — สรุป · ป้าย ค่า · …, ≤ 400 ตัวอักษร) เพราะมันคือสิ่งที่โชว์บนหน้าจอล็อก/ตัวอย่างแชต ไม่ใช่ตัวการ์ด
4. **ตัดข้อความยาวด้วย "…" ทุกช่อง** — หัวเรื่อง 100, สรุป/ประโยค 300, ป้าย 24, ค่า 120, ปุ่ม 20, altText 400
5. **ปุ่มเปิดในเบราว์เซอร์ของเครื่อง** (`?openExternalBrowser=1`) ไม่ใช้ LIFF — เบราว์เซอร์ในแอป LINE ขอให้ล็อกอินใหม่และบางฟีเจอร์ใช้ไม่ได้
6. **ลิงก์เป็น path ภายในเท่านั้น** — path แปลก/ลิงก์นอก/ว่าง → ตกไป `/today` (ไม่เคยพาออกนอกระบบ)
7. สี ฟอนต์ ใช้ชุดเดียวกับแอป (ดู `docs/UI-DESIGN-KNOWLEDGE.md`): หัวเรื่อง `#07707F`, ข้อความ `#1F2A30`, ป้ายรอง `#5B6B73`, ปุ่ม `#FF7A6B` (โคราลคือสีปุ่ม CTA)
8. ข้อความเป็นภาษาของ **ผู้รับ** และใช้ชื่อแอปที่แอดมินตั้ง

### 3.3 ตารางข้อจำกัดความยาว

| ส่วน                    | ขีดจำกัดของเรา | หมายเหตุ                                                         |
| ----------------------- | -------------- | ---------------------------------------------------------------- |
| หัวเรื่อง               | 100 ตัวอักษร   | ตัดด้วย "…"                                                      |
| บรรทัดรายละเอียด        | **8 บรรทัด**   | รวมบรรทัดสรุปและแถว "ป้าย: ค่า" ทั้งหมด (ส่วนเกินไม่ขึ้นบนการ์ด) |
| ประโยค/สรุป (ไม่มีป้าย) | 300 ตัวอักษร   |                                                                  |
| ป้าย (label)            | 24 ตัวอักษร    |                                                                  |
| ค่า (value)             | 120 ตัวอักษร   |                                                                  |
| ข้อความบนปุ่ม           | 20 ตัวอักษร    | มาจาก `notifOpenApp` ("เปิดแอป" / "Open the app")                |
| `altText`               | 400 ตัวอักษร   | ขีดของ LINE                                                      |

เทสบังคับ: ส่งข้อความยาว 2,000 ตัว × 20 บรรทัด → ได้ altText ≤ 400, ส่วนของ body ≤ 9 ชิ้น (หัวเรื่อง + 8 บรรทัด), และไม่มีข้อความใดยาวเกิน 300

## 4. จากข้อความไปเป็นการ์ด

```ts
// 1) ฟีเจอร์สร้าง Notice (ภาษาของผู้รับ — dictFor(userId))
noticeBody("สินค้าถูกส่งออกแล้ว ตามเลขพัสดุได้ด้านล่าง", [
  ["ขนส่ง", "Flash Express"],
  ["เลขพัสดุ", "TH0123456789"],
]);
// → "สินค้าถูกส่งออกแล้ว ตามเลขพัสดุได้ด้านล่าง\nขนส่ง: Flash Express\nเลขพัสดุ: TH0123456789"

// 2) ตอนส่ง: parseNoticeBody แยกบรรทัด
//    บรรทัดที่มี ": " และส่วนหน้า ≤ 24 ตัว → { label, value }  →  แถวสองคอลัมน์
//    บรรทัดอื่น (รวมประโยคที่มี ":" ยาว)  → { label: null, value } →  ข้อความเต็มบรรทัด
```

กฎการแยก **ตั้งใจให้เข้ม**: เฉพาะ "ป้ายสั้น" ก่อน `": "` ที่นับเป็นป้าย เพื่อให้ประโยคปกติที่บังเอิญมีเครื่องหมาย `:` ไม่ถูกหั่นเป็นสองคอลัมน์

### 4.1 รูปแบบของเนื้อหา 3 แบบที่ใช้จริง

| แบบ                 | ตัวอย่าง                                                                       | โครง body                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| **สรุปอย่างเดียว**  | เตือนเช็กอิน, ออเดอร์ถูกยกเลิก                                                 | `noticeBody("ประโยคสรุป")`                                                                                |
| **สรุป + ป้าย/ค่า** | ชำระเงินสำเร็จ (ใช้ได้ถึง), จัดส่ง (ขนส่ง/เลขพัสดุ), ทดลองใช้ใกล้หมด (สิ้นสุด) | `noticeBody("สรุป", [["ป้าย","ค่า"], …])`                                                                 |
| **รายการ (bullet)** | แจ้งเตือนสต็อก/วันหมดอายุของสาขา                                               | บรรทัดสรุป + บรรทัด `• ชื่อสินค้า · ล็อต … · หมดอายุ … · เหลือ …` (ไม่มี `": "` จึงเป็นข้อความเต็มบรรทัด) |

ป้ายที่ใช้ซ้ำอยู่ในพจนานุกรมเป็นชุด `notifLabel*` (สิ้นสุด, ใช้ได้ถึง, หมายเหตุ, เลขอ้างอิง, ช่องทางติดต่อ, ผลตรวจล่าสุด …) เพื่อให้ป้ายเดียวกันเขียนเหมือนกันทุกการ์ด

## 5. ลิงก์ของปุ่ม

```ts
export function appOpenUrl(baseUrl: string, path: string | null): string {
  const p = safeHref(path) ?? "/today"; // ต้องขึ้นต้นด้วย "/" ไม่ใช่ "//" และ ≤ 300 ตัว
  const url = `${baseUrl.replace(/\/+$/, "")}${p}`;
  return `${url}${url.includes("?") ? "&" : "?"}openExternalBrowser=1`; // ไปเบราว์เซอร์ของเครื่อง
}
```

| ตัวอย่างเข้า                          | ผล                                                           |
| ------------------------------------- | ------------------------------------------------------------ |
| `/subscription`                       | `https://…/subscription?openExternalBrowser=1`               |
| `/a?b=1`                              | `https://…/a?b=1&openExternalBrowser=1` (ต่อ `&` ไม่ใช่ `?`) |
| `https://evil.example` / `//x` / ว่าง | `https://…/today?openExternalBrowser=1`                      |

- **ไม่ใช้ LIFF** (`liff.line.me`) โดยตั้งใจ — เทสยืนยันว่า URL ไม่มี `liff.line.me`
- base URL ของเว็บมาจากการตั้งค่าไซต์ (`getConfiguredSiteUrl()`) หรือ `URL` ของ Netlify
- เบราว์เซอร์ของเครื่องอาจยังไม่ล็อกอิน — ส่วนนี้เป็นพฤติกรรมปกติของหน้าในแอป (ไม่มีอะไรพิเศษสำหรับการ์ด)

## 6. ข้อควรรู้ในการเขียนข้อความ (เนื้อหาของการ์ด)

1. **หัวเรื่องบอกเหตุการณ์ + สิ่งที่เกี่ยวข้อง** ("ออเดอร์ RS-000492 จัดส่งแล้ว") ไม่ใช่ "มีการแจ้งเตือนใหม่"
2. บรรทัดสรุปบอกผลและสิ่งที่ผู้รับต้องทำต่อ (ถ้ามี) หนึ่งประโยค
3. ข้อมูลที่ผู้รับต้องใช้ทันทีใส่เป็นแถว `ป้าย: ค่า` (เลขพัสดุ, วันหมดอายุ, ช่องทางติดต่อ)
4. **ห้ามใส่เรื่องอ่อนไหว** — หัวข้อการปรึกษา คำแนะนำ ชื่อยา ค่าผลแล็บ: บอกแค่ว่ามีเรื่อง แล้วให้เปิดแอปดู
   (ข้อยกเว้นที่เจ้าของกำหนดเอง: การแจ้งเตือนสต็อกของสาขาระบุชื่อสาขาและสินค้า เพราะผู้รับเป็นเจ้าหน้าที่ในงานของตน)
5. ข้อความระบุ **เลขอ้างอิง/วันที่** เพื่อให้การ์ดตอบ "อะไร/เมื่อไร" ได้เอง — วันที่ใช้รูปแบบไทย (พ.ศ.) ตามภาษาผู้รับ
6. ข้อความเขียนในพจนานุกรม (`notif*`) ทั้งสองภาษา ใส่ตัวแปรด้วย `{n}`, `{no}`, `{days}`; ห้ามต่อสตริงในโค้ด
7. หนึ่งเหตุการณ์ = หนึ่งการ์ด — รายการหลายชิ้นรวมเป็นการ์ดเดียวแบบ bullet (แล้วตัดด้วย "และอีก N รายการ" — ดูข้อสังเกตด้านล่าง)

## 7. กฎที่ห้ามละเมิด

1. การ์ดสร้างจาก `Notice.body` ตอนส่งเท่านั้น — ห้ามมีข้อความของ LINE ที่ไม่ผ่าน `buildLineMessage`
2. **ทุกช่องข้อความต้องถูกตัด** (`clip`) — LINE ปฏิเสธทั้งข้อความถ้าช่องเดียวเกิน
3. `altText` ต้องมีรายละเอียด ไม่ใช่แค่หัวเรื่อง
4. ปุ่มต้องเป็นลิงก์ภายใน (`safeHref`) + `openExternalBrowser=1`; ห้ามใช้ LIFF
5. ห้ามใส่ข้อมูลอ่อนไหวในการ์ด (หัวข้อ §6.4)
6. สี/ฟอนต์ตามแบรนด์; ปุ่มหลักเป็นโคราลพร้อมข้อความเข้ม
7. ภาษาของผู้รับ และชื่อแอปตามที่แอดมินตั้ง

## 8. ข้อสังเกตจากโค้ดจริง (ควรรู้ก่อนลอก)

| เรื่อง                             | รายละเอียด                                                                                                                                                                                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **การ์ดโชว์ได้แค่ 8 บรรทัด**       | `parseNoticeBody(...).slice(0, 8)` — แจ้งเตือนสต็อกใส่รายการสูงสุด 10 บรรทัด + บรรทัด "และอีก N รายการ" แต่บนการ์ด LINE จะเห็นเฉพาะบรรทัดสรุป + 7 รายการแรก (ส่วนที่เหลืออยู่ในกล่องแจ้งเตือนในแอป) ถ้าต้องการให้เห็นครบบนการ์ด ให้ลดจำนวนรายการต่อการ์ดให้พอดี หรือเพิ่มขีด 8 |
| **บรรทัดที่มี ": " ใกล้ต้นประโยค** | ถ้าประโยคมี `": "` ภายใน 24 ตัวแรก จะถูกแยกเป็นป้าย/ค่าโดยไม่ได้ตั้งใจ — เขียนประโยคสรุปโดยเลี่ยง `ข้อความสั้น: …` หรือใช้ `noticeBody` ใส่เป็นแถวป้าย/ค่าให้ชัดเจน                                                                                                            |
| **ไม่มีรูป/ไอคอนในการ์ด**          | ใช้ข้อความล้วน (เรียบ โหลดเร็ว ไม่ต้องโฮสต์รูป) ถ้าต้องการ hero image ให้เพิ่ม `hero` ใน bubble และโฮสต์รูป HTTPS สาธารณะ                                                                                                                                                      |
| **ปุ่มเดียว**                      | ทุกการ์ดมีปุ่ม "เปิดแอป" ปุ่มเดียว ไม่มีปุ่มรอง (เช่น "ปฏิเสธ")                                                                                                                                                                                                                |

## 10. ลอกไปใช้อย่างไร

1. กำหนดชนิด `Notice` (kind, title, body, href, category, urgent, dedupeKey) และ `noticeBody` / `parseNoticeBody` / `safeHref` (pure, เทสได้)
2. `buildLineMessage(notice, { baseUrl, openLabel })` → Flex bubble ตามโครง §3 (หัวเรื่อง, รายการ ≤ 8, ปุ่ม) + `altText` ที่มีรายละเอียด + `clip` ทุกช่อง
3. `appOpenUrl` พร้อม `openExternalBrowser=1`
4. ตัวสร้างข้อความต่อเหตุการณ์อยู่ที่เดียว ใช้พจนานุกรมสองภาษา (ป้ายชุด `notifLabel*`)
5. ปรับสีให้เป็นแบรนด์ของคุณ (หัวเรื่อง, ข้อความ, ป้ายรอง, ปุ่ม) — ตรวจ contrast เหมือนหน้าเว็บ
6. ทดสอบกับบัญชี LINE จริงสักครั้ง (ดูทั้งในแชตและบนหน้าจอล็อก) — LINE Flex Message Simulator ช่วยตรวจ JSON ก่อนได้
7. เทส: การ์ดมี type/altText/ปุ่ม, ตัดความยาว (ข้อความ 2,000 ตัว), `altText` ≤ 400, ลิงก์ภายในเท่านั้นและไม่มี LIFF, `parseNoticeBody` (ป้ายสั้น/ประโยคยาว/บรรทัดว่าง)
