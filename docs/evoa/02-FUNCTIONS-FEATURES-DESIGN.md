## วิธีใช้เอกสารนี้

- ทุกฟีเจอร์มีรหัส (เช่น `C-04`) และ **ระดับความสำคัญที่ผมแนะนำ**:
  - **P0 = MVP** ต้องมีวัน Go-Live (สัปดาห์ที่ 8 ตาม timeline)
  - **P1 = Phase 2** (เดือนที่ 3–4) — เพิ่มรายได้/ลดงานคน
  - **P2 = Phase 3** (เดือนที่ 5+) — ต่อยอด Super App / ข้อมูล
- คอลัมน์ **ตัดสินใจ** ให้คุณกรอก: `✅ ทำ` · `⏸ เลื่อน` · `❌ ไม่ทำ` · หรือย้าย P
- §6 คือ **คำถามที่ต้องตัดสินใจก่อนเริ่มพัฒนา** (กระทบสถาปัตยกรรม)

## 1. เป้าหมายของระบบ (จาก requirement)

| เป้าหมาย | ตัวชี้วัด |
| --- | --- |
| ลดคอขวดหน้าด่าน VOA | % ผู้เดินทาง VOA ที่ผ่านช่อง E-VOA, เวลารอที่สนามบิน |
| สตม. คัดกรองล่วงหน้า 100% | ใบสมัครทุกใบผ่าน Blacklist/Watchlist ก่อนขึ้นเครื่อง |
| อนุมัติเร็ว | Regular 2–3 วัน (24–72 ชม.), Express < 24 ชม. |
| ทุกชาติ ทุกภาษา | รองรับทุกสัญชาติที่ใช้ VOA (ไม่ใช่แค่จีน) |
| Zero cost to government | รายได้มาจาก Processing fee + Express premium + ค่าคอมมิชชันบริการเสริม |
| รายได้ | Base case 3% ของ 23 ล้านคน = 690,000 คน/ปี × 600 THB = 414 ล้านบาท (+ ค่าวีซ่าเข้ารัฐ 1,380 ล้านบาท) |

### 1.1 Personas

| Persona | ต้องการอะไร | ความกังวล |
| --- | --- | --- |
| **นักท่องเที่ยวอิสระ** (อินเดีย, จีน, ไต้หวัน, ซาอุฯ, รัสเซีย …) ใช้มือถือ | ยื่นเร็ว ไม่ต้องต่อคิว รู้ชัดว่าต้องเตรียมอะไร | เว็บนี้ของจริงไหม? ข้อมูลพาสปอร์ตปลอดภัยไหม? โดนเก็บเงินแพงไหม? |

| **พาร์ทเนอร์บริการเสริม** (ประกัน, SIM, รถ, Fast Track) | รู้ล่วงหน้าว่าใครมาเมื่อไร, ยืนยันการใช้บริการง่าย | ได้ข้อมูลช้า/ผิด, การจ่ายเงินส่วนแบ่ง |

## 4. สถานะใบสมัคร (State Machine)

```
DRAFT ──(ส่ง+รอชำระ)──► AWAITING_PAYMENT ──(หมดเวลา)──► EXPIRED
                              │(จ่ายสำเร็จ)
                              ▼
                            PAID ──► PRE_CHECK (Ops/อัตโนมัติ) ──(เอกสารไม่ผ่าน)──► ACTION_REQUIRED ─┐
                                          │(ผ่าน)                                         ▲            │(ลูกค้าแก้)
                                          ▼                                               │            │
                                   SUBMITTED_TO_IMMIGRATION ──► UNDER_REVIEW ──(สตม. ขอเพิ่ม)─┘◄───────────┘
                                          │(ส่งไม่สำเร็จ→retry)        │
                                          ▼                           ├──► APPROVED ──► (วันเดินทาง) USED / NO_SHOW
                                   SUBMISSION_FAILED (Ops)            └──► REJECTED ──► REFUND (ตามนโยบาย)
ยกเลิกได้ก่อน SUBMITTED → CANCELLED (+REFUND)
ระดับกลุ่ม: ALL_APPROVED / PARTIALLY_APPROVED / ALL_REJECTED
```
