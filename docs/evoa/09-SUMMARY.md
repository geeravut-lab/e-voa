## Phase 0 — พื้นฐาน
**ทำแล้ว ✅**
- เว็บ Next.js 16 + Supabase (สิงคโปร์) + Vercel, แบรนด์ ThaiPass e-VOA (อัปโหลดโลโก้/ไอคอน/ชื่อได้จากหลังบ้าน)
- หน้าแรกแบบการ์ดภาพประกอบ, แถบล่างบนมือถือ, เมนู "เพิ่มเติม", ปุ่มทุกปุ่มมี spinner, ภาพ banner ธีมไทย
- เข้าสู่ระบบด้วยอีเมล+รหัสผ่าน, Google, LINE (ผ่าน Aivora) · โปรไฟล์ + ภาษา
- **9 ภาษา:** EN, TH, 简体中文 ครบ · HI, AR (ขวาไปซ้าย), RU, KO, JA, 繁體中文 แปลทุกข้อความที่ผู้เดินทางเห็น (หน้ากฎหมาย/FAQ/คู่มือ/บทความและข้อความหลังบ้านยังเป็นอังกฤษ) · ตัวเลือกภาษาแบบ drop-down
- Live sync (หน้าอัปเดตเองเมื่อข้อมูลเปลี่ยน ~1.3 วินาที), PWA (ปุ่มติดตั้งเป็นแอปในคลิกเดียวบน Chrome/Edge/Android)
- Feature switches, ผู้ดูแล/เจ้าของ, audit trail (เปิด/ปิดการเก็บและเลือกชนิด event ได้), analytics พื้นฐาน, การแจ้งเตือนในแอป
- กฎ "ไม่มีสี hex นอก globals.css", ตัวจำลองคู่ค้า + กติกาทดสอบกับตัวจำลองก่อนเสมอ
**ค้าง**
- 🟡 ตั้ง Vercel env ที่จำเป็นให้ครบ (`SUPABASE_SERVICE_ROLE_KEY`, `DATA_ENCRYPTION_KEY`, `CRON_SECRET`, `STRIPE_*`) — ดู `/api/health`
- 🟡 SMTP (Resend) สำหรับลืมรหัสผ่านและอีเมลใบเสร็จ
- 🟡 Cron: Vercel Hobby รันวันละครั้ง (ถ้าต้องการถี่กว่านั้น ใช้ Supabase pg_cron หรือแผนที่สูงขึ้น)
- ⬜ เข้าสู่ระบบด้วย Apple/WeChat/Kakao · ⬜ 2FA/Passkey · ⬜ ยื่นแบบ Guest · ⬜ สกุลเงินที่ชอบ

## Phase 1 — เชื่อม สตม. + ข้อมูล
**ทำแล้ว ✅ (กับตัวจำลอง)**
- ตารางทั้งหมด + RLS, เครื่องสถานะในฐานข้อมูล (ตรวจครบทุกคู่สถานะ), SLA 24/72 ชม.
- ตัวส่งใบสมัครไป สตม. (คิว + retry), รับผลทาง callback + polling สำรอง, ส่งเอกสารเพิ่ม, ซิงก์รายการอ้างอิง
- เข้ารหัสเลขพาสปอร์ตและไฟล์เอกสาร, ดูได้เฉพาะเจ้าของ/แอดมินและมีบันทึก, ลบเอกสารตามเวลาเก็บรักษา
- **ตัวจำลอง สตม. ในระบบจริง** (`/admin/immigration`): เปิดแล้วกด "ส่งใบสมัครที่รออยู่" และจำลองอนุมัติ/ปฏิเสธ/ขอข้อมูลเพิ่มในหน้าใบสมัคร (ถ้าเชื่อมจริงแล้ว ระบบใช้ของจริงเสมอ)
**ค้าง**
- ⬜ **API จริงของ สตม.** (ต้องการสเปกและ credential; คำถามค้างอยู่ใน 06-MOCK-PARTNERS.md)
- ⬜ ส่งรายชื่อให้ช่อง E-VOA lane · ⬜ เชื่อม TDAC · 🟡 ตรวจก่อนส่งแบบอัตโนมัติเท่านั้น (ยังไม่มีคนตรวจสุ่ม)

## Phase 2 — ยื่นและชำระเงิน
**ทำแล้ว ✅**
- เช็คสิทธิ์ตามสัญชาติ (`/eligibility`), ค่าธรรมเนียมและกติกาคืนเงิน, checklist, FAQ + ค้นหา, คู่มือสนามบิน, หน้า "เว็บทางการ" และคำเตือนเว็บปลอม, ตรวจสถานะโดยไม่ต้อง login
- Wizard 4 ขั้น: ทริป+แพ็กเกจ (Regular ≥72 ชม., Express ≥24 ชม.) → ผู้เดินทาง+เอกสาร → บริการเสริม → ตรวจทาน+จ่าย, หลายคนต่อทริป จ่ายครั้งเดียว
- ถ่ายรูปหน้าพาสปอร์ตอ่านบนเครื่อง (ตรวจ check digit), selfie ด้วยกล้อง, ตรวจรูปถ่าย (ใบหน้า/พื้นหลัง/แสง), ดูไฟล์ที่อัปโหลด, บันทึกร่างอัตโนมัติ, ลงลายเซ็น+คำประกาศ, ความยินยอม PDPA
- กฎตรวจ (พาสปอร์ต ≥180 วัน, พำนัก ≤15 วัน, ตั๋วขากลับ, เอกสารครบ), ยื่นเพิ่มเอกสาร, ยกเลิก/เปลี่ยนวัน, อัปเกรดเป็น Express
- Stripe (โหมดทดสอบ): ตรวจยอดซ้ำ, webhook ตรวจลายเซ็น, ใบเสร็จ (หน้าเว็บ + PDF + อีเมล), คืนเงินตามนโยบาย + เจ้าหน้าที่คืนกรณีพิเศษ, ใบกำกับภาษี (PDF ไทย)
- ติดตามสถานะ `/trips`, **E-VOA Pass** (QR, พิมพ์/บันทึกรูป, ตรวจผ่าน QR), หลังบ้านคิวงาน (SLA, เอกสาร, บันทึกภายใน, ขอให้แก้, ส่งซ้ำ, ยกเลิก)
- สมุดผู้เดินทาง `/travelers`, rate limit, error log `/admin/errors`
**ค้าง**
- 🟡 **ลองจ่ายผ่านหน้า Stripe จริงหนึ่งครั้ง** (บัตร 4242…) และลงทะเบียน webhook
- 🟡 **ใส่รายชื่อประเทศ VOA/ยกเว้นวีซ่าที่ `/admin/eligibility`** (ต้องมาจากประกาศทางการ ระบบไม่เดาเอง)
- 🟡 ข้อความ `privacy`/`terms` เป็นร่าง ต้องให้ที่ปรึกษากฎหมายตรวจ · 🟡 รายละเอียดเคาน์เตอร์/ช่องของสนามบินต้องยืนยันกับ สตม./สนามบิน
- ⬜ Gateway ในประเทศ · ⬜ หลายสกุลเงิน · ✅ จ่ายภายหลังด้วยลิงก์ · ⬜ นำส่งค่าวีซ่าให้รัฐ · ✅ เตือนก่อนหมดเวลาชำระ
- ✅ รอบล่าสุด: อีเมลแจ้งสถานะ, ดาวน์โหลด/ลบข้อมูลของฉัน (PDPA), โค้ดส่วนลด, ยื่นซ้ำจากใบสมัครเก่า, จัดการ FAQ/ข่าวจากหลังบ้าน, รายงานกระทบยอดกับ Stripe รายวัน
- ⬜ ผู้ให้บริการข้อมูลเที่ยวบินจริง · ⬜ AI ดึงข้อมูลจากเอกสาร · ⬜ ค้นชื่อโรงแรมอัตโนมัติ · ⬜ เตือนพาสปอร์ตเดียวกันทริปทับกัน · 🟡 ตรวจ accessibility อัตโนมัติผ่านแล้ว · ⬜ ลองด้วย screen reader จริง
- 🟡 อีเมลแจ้งสถานะ: ทำแล้ว แต่ต้องตั้ง `RESEND_API_KEY` + โดเมนผู้ส่งที่ยืนยันแล้ว · ✅ Web Push · ✅ เตือนก่อนบิน · ⬜ จัดการบทความ SEO จากหลังบ้าน (FAQ และข่าวทำแล้ว)

## Phase 3 — บริการเสริม

## Go-live gate (ยังไม่เริ่ม ⬜)
UAT กับ สตม. · ตรวจความปลอดภัย/pen-test · load test · ตรวจ PDPA/GDPR · ถอน key เก่าที่พบในเอกสารเก่า · ✅ CI อัตโนมัติ · ซ้อม backup/restore · ตรวจ accessibility (WCAG: อัตโนมัติผ่านแล้ว เหลือลองกับ screen reader จริง)

## เรื่องที่ต้องรู้
- **ห้ามเปลี่ยน `DATA_ENCRYPTION_KEY` อีก** — ข้อมูลและเอกสารที่เข้ารหัสด้วยคีย์เก่าจะอ่านไม่ได้
- ฐานข้อมูลจริงมีรายการอ้างอิงตัวอย่าง (ติดป้าย sample) เพื่อลอง wizard — **อย่ารับใบสมัครจริงจนกว่าจะซิงก์จาก สตม.** ครั้งแรก
- ข้อมูลทดสอบเก่าค้างในฐานข้อมูลจริง: ผู้ใช้ทดสอบ 17 ราย และแถว `partner_packages` จากตัวจำลอง 7 แถว — รอคำอนุญาตจากคุณก่อนลบ
- ข้อความ "ผู้ให้บริการที่ได้รับอนุญาต" ห้ามใช้จนกว่าจะเป็นความจริง
