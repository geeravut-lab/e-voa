## 1. ภาพรวม

### 1.1 ระบบคืออะไร
เว็บแอปแบบ mobile-first (PWA) ที่ผู้เดินทางใช้เตรียมการเดินทางไปไทย ประกอบด้วย 3 ชั้น:
1. **แกนของโดเมนเดิม (ไม่อธิบายที่นี่):** ยื่นวีซ่า ตรวจสิทธิ์ ใบสมัคร Pass สถานะ ค่าธรรมเนียม
2. **ฟังก์ชันรอบแกนที่ใช้ซ้ำได้กับโดเมนไหนก็ได้:** บัญชี, หลายภาษา, แจ้งเตือนหลายช่องทาง, ผู้ช่วย AI, FAQ/ข่าว/บทความ, เอเจนซี่, พาร์ทเนอร์ (voucher), หลังบ้านหลายระดับสิทธิ์, รายงาน, ความปลอดภัยและ PDPA
3. **ชุดเครื่องมือนักท่องเที่ยว:** เบอร์ฉุกเฉิน, บัตรวลีภาษาไทย, เช็กกฎ, Stay Guard, TDAC, อากาศ/ฝุ่น/คำเตือนทางการ, คู่มือเมื่อเกิดเหตุ, ตัวช่วยเช่ายานพาหนะ, ตู้เอกสารออฟไลน์, เช็กอินครอบครัว

## 2. สถาปัตยกรรมและรูปแบบโค้ดที่ใช้ซ้ำได้

### 2.1 โครงโฟลเดอร์
```
src/
  app/                 # หน้าและ route (App Router)
    <page>/page.tsx    # หน้า (Server Component) ดึงข้อมูลเอง
    actions/*.ts       # Server Actions แยกตามเรื่อง (admin.ts, family.ts, ...)
    api/               # route handler: cron/tick, live, health, webhook
    admin/…            # หลังบ้าน (ทุกหน้าเรียก requireAdminPage)
  components/          # UI ที่ใช้ร่วม (AppShell, Nav, Buttons, ActionForm, …)
  config/              # nav.ts (เมนูแหล่งเดียว), features.ts (สวิตช์ฟีเจอร์), theme.ts, events.ts
  lib/                 # ตรรกะ: auth, roles, settings, notify, messaging, ai, conditions, family, vault, content, …
    i18n/              # langs.ts, server.ts, dict/<lang>.ts
    supabase/          # client.ts (เบราว์เซอร์), server.ts (cookie), admin.ts (service role)
  proxy.ts             # รีเฟรช session ของ Supabase ทุกคำขอ + รับ ?lang=
supabase/migrations/   # SQL แบบเพิ่มอย่างเดียว (idempotent)
public/                # sw.js, offline*.html, icons, manifest
tests-live/            # ทดสอบกับฐานข้อมูลจริง
tools/                 # mock-partners (ตัวจำลองคู่ค้า), infographic
docs/evoa/             # เอกสาร
```

### 2.2 กฎโค้ด (ทำให้ระบบนิ่งและขยายได้)
1. **Server Component ดึงข้อมูล, Client Component เฉพาะที่ต้องโต้ตอบ** (`"use client"`) ข้อมูลส่วนบุคคลไม่ผ่าน client bundle
2. **Server Action คืนรหัสข้อผิดพลาด `err_*` ไม่คืนประโยค** หน้าจอแปลรหัสเป็นข้อความตามภาษา (`errorText(code, t)`) จึงแปลได้ครบและทดสอบง่าย
3. **ชนิดผลลัพธ์ของ action:** `ActionResult = { ok: true, message? } | { ok: false, error } | null` ใช้กับ `ActionForm` (หัวข้อ 3.6)
4. **การเขียนที่ไม่ตรงแถวไม่ใช่ความสำเร็จ:** ทุกการเขียนสำคัญใช้ `.select("id")` แล้วตรวจจำนวนแถว (`length !== 1` → ผิดพลาด)
5. **เขียนครั้งเดียวต่อเหตุการณ์ด้วย compare-and-set:** เช่น งานเตือนตั้ง `reminded_at` ด้วยเงื่อนไข `next_due_at = <ค่าที่อ่านมา>` และ `reminded_at` ยังไม่ถูกตั้ง ถ้ามีงานสองตัวรันพร้อมกัน มีตัวเดียวที่ได้แถว (เคยพบบั๊กอีเมลซ้ำจากการตรวจแค่เวลา)
6. **Fail open สำหรับการตั้งค่า:** อ่านค่าไม่ได้ → ใช้ค่าเริ่มต้นในโค้ดแล้วทำงานต่อ (`getSetting(key, default)`) ไม่ทำให้หน้าล้ม
7. **ไม่บันทึกว่า "ผ่าน" สิ่งที่ยังไม่ได้ตรวจ:** มีสถานะ pending จริง (การจ่ายเงิน เอกสาร การอนุมัติ)
8. **ตรรกะบริสุทธิ์แยกไฟล์ (`pure`)** ไม่นำเข้า server/DB เพื่อให้หน้า, งานตามเวลา และเทสต์ใช้ร่วม เช่น `roles.ts`, `family/rules.ts`, `content/rich.ts`, `channel-links.ts`, `live/watch.ts`
9. **เมนูเป็นข้อมูลชุดเดียว** (`src/config/nav.ts`) ทุกเมนูมาจากตารางนี้ (หัวข้อ 3.3)
10. **ข้อความ UI ทั้งหมดผ่านพจนานุกรม** `src/lib/i18n/dict/*` ไม่ฝังข้อความในคอมโพเนนต์ (ยกเว้นเนื้อหายาวที่มีโครงต่อภาษาในไฟล์เนื้อหา)
11. **สีอยู่ที่ `globals.css` เท่านั้น** มีสคริปต์ `lint:colors` ตรวจ (allowlist เฉพาะไฟล์ที่ต้องมีสีในเนื้อหา เช่น SVG ภาพ PNG)
12. **แบรนด์มาจากระบบ** (`/brand/logo`, `/brand/favicon`, `getT().brandName`) เปลี่ยนจากหลังบ้านได้ ห้ามฝังชื่อ/โลโก้ในคอมโพเนนต์

### 2.3 การพิสูจน์ตัวตนและสิทธิ์
- **เข้าสู่ระบบ:** อีเมล+รหัสผ่าน (สมัคร/ลืมรหัสผ่าน), Google (OAuth ของ Supabase), LINE (ผ่านศูนย์กลาง SSO "Aivora" แลกโทเค็นที่ `/sso/callback`) เปิด/ปิดแต่ละวิธีได้ด้วย feature flag (`login_google`, `login_line`, `login_email`) ที่ `src/app/login/LoginForm.tsx`
- **จุดหมายหลังล็อกอิน (`?next=`)** ผ่าน `safeNext()` (`src/lib/safe-next.ts`): รับเฉพาะพาธในเว็บเอง (ขึ้นต้น `/` ไม่ใช่ `//` ไม่มีอักขระควบคุม) กัน open redirect
- **การนำทางหลังล็อกอินใช้ hard navigation** (`window.location.assign`) เพื่อให้คำขอถัดไปมีคุกกี้ session ใหม่
- **Session:** `src/proxy.ts` (Next.js 16 proxy แทน middleware) เรียก `supabase.auth.getUser()` ทุกคำขอเพื่อรีเฟรชคุกกี้ **ไม่ทำ access control** หน้าและ action ตรวจเอง Supabase ล่ม → แสดงเป็นผู้เยี่ยมชม ไม่ล้มทุกคำขอ
- **ผู้เยี่ยมชม (ยังไม่ล็อกอิน)** เห็นหน้าสาธารณะทั้งหมด การ์ด/เมนูที่ต้องล็อกอินมีไอคอนกุญแจ และพาไป `/login?next=<ปลายทาง>`
- **สิทธิ์เจ้าหน้าที่ (`src/lib/roles.ts`)** ความสามารถ (capability) 6 ด้าน: `ops` (คิวงาน), `finance` (รายได้ กระทบยอด ส่วนลด), `content` (FAQ ข่าว บทความ สนามบิน เครื่องมือ), `config` (ตั้งค่าระบบ), `audit` (บันทึก/สถิติ), `staff` (จัดการเจ้าหน้าที่) บทบาท: `manager` (ทุกอย่างยกเว้น staff), `operator` (ops), `finance` (finance+audit), `editor` (content) และ **owner** (ทุกอย่าง) บทบาทที่ไม่รู้จัก = ไม่มีสิทธิ์ (least privilege)
- **การบังคับสิทธิ์จริงอยู่ที่หน้าและ action:** หน้าแอดมินเรียก `requireAdminPage(cap)` และ action เรียก `requireAdminAction(cap)` เป็นบรรทัดแรก **การซ่อนเมนูไม่ใช่การควบคุมการเข้าถึง**
- **บัญชีผู้ดูรายงาน (report viewer)** อ่านสถิติอย่างเดียวที่ `/gov` (เมนูลัดเฉพาะกลุ่มนี้)
- **RLS ของ Supabase** เปิดทุกตาราง ตารางความเป็นส่วนตัวสูง (เช็กอินครอบครัว ฯลฯ) ไม่มีนโยบายให้เบราว์เซอร์อ่านเลย เข้าถึงผ่านเซิร์ฟเวอร์ด้วย service role เท่านั้น

### 2.4 ความปลอดภัยและความเป็นส่วนตัว (สรุป)
- ความลับ (service role, VAPID, คีย์ผู้ให้บริการ) อยู่ฝั่งเซิร์ฟเวอร์ ไม่มี `NEXT_PUBLIC_` และไม่เข้าไฟล์/เอกสาร/commit
- เลขพาสปอร์ตและไฟล์เอกสารเข้ารหัสด้วยคีย์แอป (`DATA_ENCRYPTION_KEY` **ห้ามเปลี่ยน** ข้อมูลเก่าจะอ่านไม่ได้)
- **Rate limit** ตามผู้ใช้/IP (`rate_limits`, `src/lib/ratelimit.ts`) เช่น ตรวจสถานะ 10 ครั้ง/10 นาที/IP, ลิงก์จ่ายแทน 10/ชม., เชื่อม LINE 10/ชม., ส่งรหัส WhatsApp 3/ชม.
- **Header ความปลอดภัย** (`next.config.ts`): `X-Frame-Options: DENY`, `Permissions-Policy: camera=(self), microphone=(), geolocation=(self)` ฯลฯ
- **PDPA:** ดาวน์โหลดข้อมูลของฉัน (JSON), ลบบัญชี (ลบ/ทำให้ไม่ระบุตัวตน เก็บเฉพาะที่กฎหมายบังคับ เช่น ธุรกรรม), บันทึกความยินยอม (`consents`)
- **Audit trail:** ทุกการกระทำสำคัญของเจ้าหน้าที่ (เปิดเอกสาร ส่ง/ยกเลิก คืนเงิน ตั้งค่า) เปิด/ปิดการเก็บและเลือกชนิดเหตุการณ์ได้ (`audit_config`) บันทึกไม่เก็บเนื้อหาส่วนตัว
- **ข้อความเว็บปลอม:** แอปบอกชัดว่าเป็นผู้ให้บริการเอกชน ไม่ใช่เว็บรัฐ ทุกหน้ามีข้อความท้ายหน้า (`disclaimer`) และหน้า "ช่องทางทางการ" สอนวิธีสังเกตเว็บปลอม
- **ไม่เปิดเผยที่ผู้ใช้ไม่ต้องรู้:** เช่น เหตุผลปฏิเสธไม่ใส่ในการ์ด LINE (อาจโชว์บนหน้าจอล็อก)

### 2.5 ระบบหลายภาษา (i18n)
- **ภาษาที่รองรับ 9:** EN, TH, 简体中文, हिन्दी, العربية (ขวาไปซ้าย), Русский, 한국어, 日本語, 繁體中文 ทะเบียนที่ `src/lib/i18n/langs.ts`
- **เพิ่มภาษา:** (1) เพิ่มใน `langs.ts` (2) สร้าง `dict/<code>.ts` (3) ลงทะเบียนใน `dict/index.ts` ภาษา RTL ใส่ `dir: "rtl"` เท่านั้น
- **เลือกภาษา:** คุกกี้ `evoa_lang` → ถ้าไม่มี ใช้ `Accept-Language` (`pickLang`) → ค่าเริ่มต้น EN `?lang=th` แสดงหน้านั้นเป็นภาษานั้นเฉพาะคำขอ (สำหรับลิงก์ hreflang ไม่เปลี่ยนค่าที่บันทึก) ตัวสลับภาษา `LangSwitcher` อยู่ที่แถบข้าง/หัวมือถือ/เมนู More
- **ระดับความครบ:** EN/TH/ZH-CN พจนานุกรมครบทุกคีย์ ภาษาอื่นแปลทุกอย่างที่ผู้เดินทางเห็น ส่วนข้อความหลังบ้านที่ยังไม่แปลตกกลับเป็นอังกฤษ (`withEnglish`)
- **เนื้อหายาว** (กฎหมาย FAQ คู่มือ บทความ ชุดเครื่องมือ) เขียนเป็นโครงต่อภาษา `PerLang<T>` (`src/lib/content/types.ts`) เขียนครบ EN/TH/ZH-CN แล้วเติมอีก 6 ภาษาจากไฟล์ `content/lang/<code>-a.ts` และ `-b.ts` ภาษาที่ไม่มีเนื้อหาตกกลับ EN (`forLang`)
- **ข้อความที่ส่งออกนอกแอป** (อีเมล, LINE, WhatsApp, Push) ใช้ภาษาในโปรไฟล์ของผู้รับ (`profiles.lang`) ไม่ใช่ภาษาของผู้ที่กดทำ
- **ฟอนต์:** Plus Jakarta Sans + Prompt (หัวข้อไทย) + Noto Sans ตามชุดอักษรของภาษา มีเทสต์ล็อกว่าทุกภาษามีคีย์และ `{ตัวแทน}` ตรงกับ EN สำหรับเนื้อหาชุดเครื่องมือ

### 2.6 การตั้งค่าและสวิตช์
- **`platform_settings`** (คีย์ → JSON) เป็นที่เก็บการตั้งค่าที่แอดมินแก้ได้ เช่น `brand`, `fees`, `official_channels`, `company`, `messaging`, `ai`, `ai_routing`, `ai_prompt_extra`, `audit_config`, `automation_rules`, `feature_flags`, `toolkit_content`, `airport_notes` อ่านผ่าน `getSetting(key, default)` (แคชสั้น `SETTINGS_TTL_MS`) เขียนผ่าน `putSetting`

### 3.3 เมนู: แหล่งเดียว `src/config/nav.ts`
ตาราง `NAV` ตารางเดียวสร้าง **ทุกอย่าง**: แถบข้าง, แถบล่างมือถือ, แผ่น "เพิ่มเติม", การ์ดหน้าแรก หน้าจึงไม่มีทาง "อยู่ในเมนูหนึ่งแต่ขาดอีกเมนู" แต่ละรายการ (`NavItem`):
| ฟิลด์ | ความหมาย |
| --- | --- |
| `key`, `label`, `barLabel?`, `sub?` | รหัส, ข้อความ (คีย์พจนานุกรม), ข้อความสั้นสำหรับแถบล่าง, คำอธิบายใต้ชื่อบนการ์ด |
| `href`, `icon`, `art?`, `tone` | ปลายทาง, ไอคอนเส้น, ภาพประกอบ, โทนสีการ์ด |
| `size` | `wide` (เต็มแถว) หรือ `half` (ครึ่งแถว) ในกริด 2 คอลัมน์ |
| `area` | `traveler` หรือ `admin` (บัญชีเจ้าหน้าที่เห็นเฉพาะเมนูหลังบ้าน) |
| `auth` | ต้องล็อกอิน → ผู้เยี่ยมชมเห็นกุญแจและถูกพาไป `/login?next=…` |
| `status` | `live` หรือ `soon` (พาไป `/soon/<key>`) |
| `feature?` | ผูกกับ feature flag (ปิดแล้วหายจากทุกเมนู) |
| `cap?` | สิทธิ์เจ้าหน้าที่ที่ต้องมี (หนึ่งในรายการ) → `navAllowed()` |
| `viewerOnly?` | แสดงเฉพาะบัญชีผู้ดูรายงาน |
| `bottom?` / `home?` / `side?` | อยู่ในแถบล่าง / การ์ดหน้าแรก / แถบข้าง |
| `pin?` | การ์ดล็อกสีของตัวเอง (อัลกอริทึมกระจายสีเลี่ยงรอบมัน) |
- **`resolveHref(item, signedIn)`** คำนวณปลายทางจริง: `soon` → `/soon/<key>`, ต้องล็อกอินแต่ยังไม่ล็อกอิน → `/login?next=<ปลายทาง>` (encode แล้ว)
- **กรองตามผู้ชม** (ใน `AppShell`): flag เปิด, `viewerOnly` ตรงกลุ่ม, `area` ตรงกับ admin/traveler, และถ้าเป็นเจ้าหน้าที่ต้อง `navAllowed(caps)` — ดังนั้นพนักงานบทบาท `editor` เห็นเฉพาะเมนูเนื้อหา

### 3.4 แถบเมนูล่างบนมือถือ (`BottomBar` ใน `Nav.tsx`)
- 5 ช่อง: **ซ้าย 2 ช่อง** (ผู้เดินทาง: หน้าแรก, ทริปของฉัน — เจ้าหน้าที่: หลังบ้าน, การแจ้งเตือน), **ปุ่มกลางยกสูง** (ผู้เดินทาง: "ยื่นขอ" ไอคอนเครื่องบิน; เจ้าหน้าที่: พื้นที่แรกที่บทบาทมี เช่น คิวงาน → รายได้ → เนื้อหา → ข้อผิดพลาด), **ขวา 1 ช่อง** (ผู้เดินทาง: ช่วยเหลือ; เจ้าหน้าที่: ข้อผิดพลาด), และช่อง **"เพิ่มเติม"** (จุดสามจุด)
- ปุ่มกลาง: วงกลม 64px ไล่สี teal→primary เงาน้ำเงิน มีวงแหวน 4px สีพื้น ยกสูงขึ้น −24px
- ทุกช่องสูงขั้นต่ำ 56px (`min-h-14`) ป้ายตัวอักษร 12px ตัดข้อความด้วย `truncate` ใช้ `barLabel` (ข้อความสั้น) ถ้ามี
- **จุดแดงบนปุ่ม "เพิ่มเติม"** เมื่อมีการแจ้งเตือนที่ยังไม่อ่านของผู้เดินทาง (เจ้าหน้าที่ใช้ป้ายตัวเลขบนช่อง "การแจ้งเตือน")

### 3.5 แผ่น "เพิ่มเติม" (More sheet) และการกด Back — จุดละเอียดที่สำคัญ
แผ่นเลื่อนขึ้นจากล่าง (`rounded-t-3xl`, สูงไม่เกิน 85dvh, ฉากหลังมืด `bg-ink/40` กดปิดได้) ภายในคือเมนูทั้งหมดที่ไม่ได้อยู่ในแถบล่าง + สลับภาษา + ออกจากระบบ/เข้าสู่ระบบ
1. **ปุ่ม Back ของเครื่องปิดแผ่น แทนที่จะออกจากหน้า:** ตอนเปิดแผ่น โค้ด `pushState({ evoaSheet: true })` สงวนประวัติไว้ 1 รายการ เมื่อกด Back (`popstate`) แผ่นปิดและผู้ใช้ยังอยู่หน้าเดิม
2. **กดรายการในแผ่น → ย้อนผ่านรายการสงวนก่อน แล้วค่อยนำทาง** (`goFromSheet`): ทำให้การกด Back ครั้งเดียวหลังไปถึงหน้าใหม่ กลับมาที่หน้าที่เปิดแผ่น ไม่ต้องกดสองครั้ง
3. **ระหว่างรอหน้าใหม่ แผ่นยังเปิดและรายการที่กดมี spinner** รายการอื่นถูกปิดการกด (`disabled`) กันกดซ้ำ/กดซ้อน (`navRef` กัน double tap) เมื่อหน้าใหม่มาถึง (`pathname` เปลี่ยน) แผ่นปิดเอง
4. **ปุ่ม Esc ปิดแผ่น**, ปุ่ม ✕ มุมขวา, กดฉากหลังปิด
5. **เปิดแผ่นแล้วเลื่อนให้เห็นหน้าปัจจุบันตรงกลางทันที** (`scrollIntoView` ที่รายการ `aria-current="page"`)
6. **ปุ่มลูกศรเลื่อนขึ้น/ลง** (วงกลมลอยมุมขวา) โผล่เมื่อยังมีรายการเหนือ/ใต้ ให้คนที่เลื่อนด้วยนิ้วไม่สะดวกหรือใช้เมาส์
7. กลุ่ม "หลังบ้าน" ในแผ่นของเจ้าหน้าที่วาดต่างจากแถวธรรมดา (หัวกลุ่มพื้นทองอ่อน ขอบทอง; รายการย่อยเยื้องและมีเส้นซ้ายสีทอง)

### 3.6 ปุ่ม "กลับ" ในหน้า (`BackLink.tsx` + `PARENTS` ใน `nav.ts`)
- ทุกหน้าที่ไม่ใช่หน้าระดับบนสุด แสดงลิงก์ **"← กลับไป<ชื่อหน้าแม่>"** เหนือหัวหน้า (ลูกศรพลิกอัตโนมัติใน RTL สูงขั้นต่ำ 44px) **หน้าแม่คำนวณจากพาธ ไม่ใช้ประวัติเบราว์เซอร์** จึงกลับไปหน้าที่ถูกต้องเสมอแม้เปิดลิงก์ตรง
- ตาราง `PARENTS` เขียนครั้งเดียว (regex → ป้าย + ปลายทาง) เช่น `/trips/<id>` → "ทริปของฉัน", `/admin/queue/<id>` → "คิวใบสมัคร", `/admin/<อะไรก็ได้>` → "หลังบ้าน", `/account/*` → "บัญชี", `/soon/*` → หน้าแรก, หน้าระดับบนทั่วไปในรายการ (เช่น `/help`, `/guide`, `/toolkit`) → หน้าแรก
- **หน้าแรกของหลังบ้าน (`/admin`) ไม่มีลิงก์กลับ** (เป็นหน้าระดับบน)
- ลิงก์ย้อนใช้ `NavRowLink` (มี spinner) ดังนั้นการกดกลับก็มีฟีดแบ็กเมื่อโหลดช้า
- นอกจากลิงก์กลับ หน้าเนื้อหาย่อยมักมีปุ่ม "ทั้งหมด…" หรือลิงก์ไปหน้าที่เกี่ยวข้องท้ายหน้า (เช่น คู่มือเมื่อเกิดเหตุ → "เบอร์ฉุกเฉิน", "อากาศ", "ตัวช่วยเช่ายานพาหนะ")

### 3.7 การไฮไลต์เมนูที่กำลังใช้งาน
กฎอยู่ที่ `isActive(path, entry)` ใน `Nav.tsx` ใช้เหมือนกันทั้งแถบข้าง แถบล่าง และแผ่นเพิ่มเติม:
- แต่ละรายการมีรายการ `match` (พาธที่นับว่า "อยู่ในเมนูนี้") = `[href, /soon/<key>]`
- **หน้าแรก** (`/`) ตรงเมื่อพาธ **เท่ากับ** `/` เท่านั้น (ไม่ใช่ทุกพาธ)
- รายการทั่วไปตรงเมื่อ `พาธ === match` **หรือ** `พาธ` ขึ้นต้นด้วย `match + "/"` — เช่น `/trips/abc` ไฮไลต์เมนู "ทริปของฉัน" (หน้าลูกจึงไฮไลต์เมนูแม่)
- **`exact`** สำหรับ "หลังบ้าน" (`admin_home`): ไฮไลต์เฉพาะหน้า `/admin` เอง ไม่ใช่ทุกหน้าใต้ `/admin/*` (ถ้าไม่ตั้ง จะสว่างตลอด)
- รูปแบบการไฮไลต์: แถบข้าง/แผ่นเพิ่มเติม = พื้น `sky` + ตัวอักษร `primary`; แถบล่าง = สีไอคอน/ป้ายเป็น `primary` (ไม่ active = `muted`) ทุกที่ใส่ **`aria-current="page"`** ให้โปรแกรมอ่านหน้าจอ
- ปุ่ม **"เพิ่มเติม"** ไฮไลต์เมื่อหน้าปัจจุบันเป็นหนึ่งในรายการในแผ่น (`moreActive`) ผู้ใช้จึงรู้ว่าตัวเองอยู่ในเมนูที่ซ่อนอยู่
- ปุ่มกลาง "ยื่นขอ"/พื้นที่แรกของเจ้าหน้าที่ ไฮไลต์เมื่ออยู่ในหน้านั้นเช่นกัน
- **ป้ายตัวเลข** (เจ้าหน้าที่) บนเมนู "การแจ้งเตือน" แสดงจำนวนเรื่องที่รอดำเนินการ (≥ 100 เป็น "99+" ในแถบข้าง, ≥ 10 เป็น "9+" บนแถบล่าง/กระดิ่ง) ป้ายตัวเลขใช้สี `danger` ตัวอักษรขาว (ผ่านคอนทราสต์ AA)
- **กระดิ่งมุมขวาบน:** ชื่อสำหรับโปรแกรมอ่านหน้าจอขึ้นต้นด้วยตัวเลขที่เห็น ("9+ การแจ้งเตือน") ตามกฎ "label in name" ของ WCAG และตัวเลขเป็น `aria-hidden`

### 3.8 ฟีดแบ็กเมื่อกด: กฎ "ทุกปุ่มทุกลิงก์ที่ใช้เวลา ต้องมี spinner"
ไม่เคยมีการกดที่ "ไม่เกิดอะไร" ใช้คอมโพเนนต์เหล่านี้ **ห้ามใช้ `<button>`/`<form>` เปล่า** กับงานที่ช้า:
| ใช้เมื่อ | คอมโพเนนต์ | พฤติกรรม |
| --- | --- | --- |
| ปุ่มส่งฟอร์ม (server action) | `SubmitButton` | อ่าน `useFormStatus`: ขณะรอแสดง spinner + `disabled` + `aria-busy` |
| ปุ่มที่ `onClick` ทำงาน async | `AsyncButton` | ครอบด้วย `useTransition` + state: spinner จนจบ (สำเร็จหรือล้มเหลว) กดซ้ำระหว่างรอถูกเมิน |
| ลิงก์การ์ด/ปุ่มนำทางใหญ่ | `AppLink` | ใช้ `useLinkStatus`: ระหว่างโหลดหน้าถัดไปมี spinner วงกลมลอยมุมขวาบนของการ์ด |
| แถวเมนู/ลิงก์ในรายการ | `NavRowLink` | spinner ที่ท้ายแถว (`ms-auto`) |
| เลือกภาษา | `LangSwitcher` | รายการที่เลือกแสดง spinner จนหน้าเรนเดอร์ใหม่เสร็จ |
- **ทุกหน้ามี `loading.tsx`** (spinner ใหญ่กลางจอ `role="status"`) กันการนำทางช้าดูเหมือนค้าง
- **ข้อยกเว้นที่ถูกต้อง:** ลิงก์ที่ออกจากเว็บไปแอปอื่น (`tel:`, ลิงก์เพิ่มเพื่อน LINE, ลิงก์ภายนอก) ไม่มี spinner เพราะหน้าเราไม่ได้โหลดอะไร
- **แบบปุ่ม** (`buttonStyles.ts`): ขนาดขั้นต่ำสูง 44px ทุกปุ่ม (พื้นที่แตะ), มี 4 รูปแบบ: `primary` (พื้นน้ำเงิน ตัวขาว), `gold` (พื้นทอง ตัวหมึก), `ghost` (ขอบ sky-line พื้นขาว ตัวน้ำเงิน), `danger` (พื้นแดง) `disabled` = โปร่ง 60% + เคอร์เซอร์ห้าม
- **`pressable`** ย่อเล็กน้อยตอนกด ใช้กับปุ่มและการ์ด

### 3.9 ฟอร์มและข้อความผลลัพธ์ (`ActionForm.tsx`)
- `ActionForm` ครอบ `<form action>` ด้วย `useActionState` ใต้ฟอร์มมีพื้นที่ผลลัพธ์ `aria-live="polite"` สูงขั้นต่ำ 24px (ข้อความไม่ทำให้หน้ากระโดด): สำเร็จ = **✓ ข้อความสีเขียว** (ค่าเริ่มต้น "บันทึกแล้ว" หรือข้อความจาก action), ล้มเหลว = **✕ ข้อความสีแดง** แปลจากรหัส `err_*` ตามภาษา
- ฟอร์มที่ต้องเก็บข้อความยาว (เช่น ตัวแก้ข่าว บทความ) ใช้ช่อง **controlled** (เก็บใน state) เพื่อไม่ให้ข้อความหายเมื่อเซิร์ฟเวอร์ปฏิเสธการบันทึก (ฟอร์มแบบ uncontrolled จะถูกล้างหลัง submit)
- ช่องกรอก: สูง ≥ 44px, ขอบ `field` 1.5px, ฟอนต์ 16px, มี `label` เสมอ (ไม่ใช้ placeholder แทน), ปรับเป็น `aria-label` ในแถบเครื่องมือหนาแน่น
- ฟอร์มขั้นตอนยาว (ยื่นขอ) บันทึกอัตโนมัติ (`form_drafts`) และตรวจก่อนส่ง (อยู่ในแกนโดเมนเดิม)
- การลบ/ย้อนกลับไม่ได้ ใช้ปุ่ม `danger` + ข้อความเตือน + (กรณีลบบัญชี) ต้องพิมพ์ยืนยัน

### 3.10 การ์ดหน้าแรกและกฎจัดวาง (`HomeCard.tsx`, `nav.ts`)
- กริด 2 คอลัมน์ `gap-3` การ์ด `wide` กินทั้งแถว (สูงขั้นต่ำ 144px) การ์ด `half` สูงขั้นต่ำ 176px
- **กฎ "ภาพไม่ทับตัวอักษร":** การ์ด half = ข้อความก่อน แล้วภาพอยู่แถวของตัวเองใต้ข้อความ (การ์ดสูงขึ้นถ้าข้อความหลายบรรทัด); การ์ด wide = ข้อความไม่เกิน 58% ซ้าย, ภาพ 42% ขวา ภาพขยายเล็กน้อยตอน hover
- ไอคอนกุญแจเล็กมุมซ้ายบนของการ์ดที่ต้องล็อกอินและผู้ใช้ยังไม่ล็อกอิน (มี `title`/`aria-label`)
- **`packCards`**: ไม่ปล่อยการ์ด half "ตัวเดียวโดดในแถว" (ถ้าตัวถัดไปเป็น wide หรือเป็นตัวสุดท้าย → ขยายเป็นเต็มแถว) ลำดับไม่เปลี่ยน เรียกกับรายการที่ **แสดงจริงหลังกรองสิทธิ์/flag แล้ว**
- **`spreadTones`**: แจกสีตามลำดับอ่านโดยให้การ์ดที่ **ติดกัน** (ซ้าย บน และสองแนวทแยงบน) ไม่ซ้ำสี, สีตระกูลใกล้กัน (ทอง/ทราย, ฟ้า/มิ้นต์) ถูกแยกกัน, ทุกสีหมุนใช้เท่า ๆ กัน และการ์ดที่ `pin` ล็อกสีของตัวเอง
- ภาพประกอบ (`Art.tsx`): ชุด SVG ของระบบเอง (apply, check, trips, travelers, extras, guide, help, ai, emergency, toolkit, notifications, account, ops, branding, ...) + ฮีโร่ธีมไทยสำหรับการ์ดทักทาย ใช้สีจากโทเค็น เบา โหลดพร้อมหน้า

### 3.11 ส่วนประกอบมาตรฐานอื่น ๆ
- **StatusBadge:** ป้ายสถานะกลมแคปซูล สีตามสถานะ (ฟ้า = ทำอยู่, มิ้นต์ = ผ่านการตรวจ/ชำระ, ทอง = ต้องทำเพิ่ม/รอ, เขียว = สำเร็จ, ชมพู/แดง = ล้มเหลว/ปฏิเสธ, ทราย = ปิด/หมดอายุ) ข้อความมาจากพจนานุกรม `st_<status>` มีคำอธิบายประกอบ `sth_<status>`
- **ตาราง:** ครอบด้วย `overflow-x-auto` พร้อม `tabIndex=0`, `role="region"` และชื่อ (เพื่อให้เลื่อนด้วยคีย์บอร์ดได้ ผ่าน axe)
- **ข้อความว่าง (empty state):** ทุกรายการมีข้อความอธิบายว่า "ยังไม่มี…" และบอกว่าจะเห็นเมื่อไร ไม่ปล่อยพื้นที่ว่าง
- **หน้า error** (`error.tsx`): บอกว่าเกิดอะไรขึ้นและทำอะไรต่อ ปุ่ม "โหลดใหม่" (`AsyncButton`), มีรหัสอ้างอิง (`digest`) และชี้เจ้าของไป `/api/health` (ตรวจตัวแปรที่ขาด)
- **หน้า "กำลังจะมา"** (`/soon/<key>`): ข้อความเป็นมิตร + Phase ที่วางแผนไว้ + ปุ่มกลับหน้าแรก (แทน 404 สำหรับเมนูที่ยังไม่สร้าง)
- **ข้อความจริงใจ:** ข้อมูลที่ยังไม่ยืนยัน (เช่น กฎเปลี่ยนบ่อย) ติดป้ายวันที่ตรวจทานล่าสุด `{when}` และบอกให้ตรวจช่องทางทางการ

### 3.12 PWA, ติดตั้งแอป และออฟไลน์
- **Manifest** (`/manifest.webmanifest`, สร้างแบบไดนามิกจากแบรนด์): ชื่อ, ไอคอน 192/512 + maskable, `display: standalone`, `start_url "/"`
- **ติดตั้งเป็นแอป** (`InstallApp.tsx` ในหน้าบัญชี): Chrome/Edge/Samsung เก็บ `beforeinstallprompt` ตั้งแต่ `<head>` (สคริปต์เล็กใน `layout.tsx`) กดปุ่มเดียวติดตั้ง ส่วน iPhone/iPad ไม่มี API จึงแสดงขั้นตอนเป็นข้อความ ตรวจว่าติดตั้งแล้วด้วย `display-mode: standalone`
- **Service worker** (`public/sw.js`): แคช **เฉพาะ** หน้าออฟไลน์, หน้าเบอร์ฉุกเฉิน (static ไม่มีข้อมูลส่วนตัว), ตู้เอกสารออฟไลน์ และไอคอน — **ไม่แคชหน้าที่มีข้อมูลผู้ใช้เด็ดขาด** (เครื่องร่วม/ผู้ใช้ที่ออกจากระบบจะแสดงข้อมูลเก่าไม่ได้) หน้าเหล่านั้นใช้ stale-while-revalidate (เปิดจากแคชทันที อัปเดตเงียบ ๆ) ปิดแล้วเปิดได้โดยไม่มีสัญญาณ ถ้าเคยเปิดครั้งหนึ่งตอนมีเน็ต
- ไฟล์ `sw.js` ตั้ง `Cache-Control: no-cache` เพื่ออัปเดตได้ทันที

### 3.13 Live sync: หน้าอัปเดตเองโดยไม่ต้องรีเฟรช (`LiveSync.tsx`, `lib/live/watch.ts`)
- ติดตั้งครั้งเดียวใน Shell เมื่อล็อกอิน การเปลี่ยนแปลงในฐานข้อมูลส่ง "ping" เปล่า (ไม่มีข้อมูลในสัญญาณ) ผ่าน Supabase Realtime หน้าจึงเรียก `router.refresh()` เพื่ออ่านซ้ำจากเซิร์ฟเวอร์ด้วยสิทธิ์ของผู้ใช้เอง
- **ห้ามรีเฟรชใต้นิ้วผู้ใช้:** ถ้ากำลังพิมพ์ในช่อง (มีค่าอยู่) จะเลื่อนรอ; หน้าแชต/ฟอร์มยาว/ล็อกอิน (`/apply`, `/help`, `/login`, `/sso`) ไม่รีเฟรชเอง
- **ฟัง topic เท่าที่หน้านั้นใช้** (`u:<userId>`; หลังบ้านเพิ่ม `admin`) เพื่อประหยัดโควต้า Realtime ต่อแท็บ
- **สำรอง:** ถ้าซ็อกเก็ตเชื่อมไม่ได้ จะ poll `/api/live?w=notif,admin` เป็นระยะ (ถี่ 12 วินาที ผู้ใช้ / 8 วินาที หลังบ้าน ช้าลง ×2 หลังเงียบ 6 ครั้ง ×4 หลัง 18 ครั้ง ไม่เกิน 60 วินาที แท็บซ่อน 30 วินาที) ได้ 401 = ออกจากระบบแล้ว หยุดถาม
- การสร้าง Realtime client ต้องใส่ `accessToken` และ `await realtime.setAuth(token)` ก่อน subscribe (ค่าเริ่มต้นเคยทำให้ช่อง private ปิดเอง)

### 3.14 การเข้าถึง (Accessibility) — ผ่านการตรวจอัตโนมัติ
- ตรวจด้วย axe-core (WCAG 2.0/2.1 A+AA) ทั้งหน้าสาธารณะ หน้าผู้เดินทางที่ล็อกอิน และหลังบ้าน ที่ 390×844 และ 1280×800 (สคริปต์ `scripts/a11y.mjs` และ `tests-live/a11y-signed-in.live.test.ts` รันใน CI)
- กฎที่ใช้: คอนทราสต์ ≥ 4.5:1 (ป้ายตัวเลขใช้ `danger` ไม่ใช้ `lotus`), พื้นที่แตะ ≥ 44px, ปุ่ม/ลิงก์มีชื่อที่เข้าใจได้ (ชื่อต้องมีข้อความที่ตาเห็น), ตารางเลื่อนโฟกัสได้, `aria-live` สำหรับผลลัพธ์, `aria-current`, `aria-busy`, ภาพ `alt` (รูปที่เจ้าหน้าที่อัปโหลดต้องใส่คำอธิบาย), ไม่ใช้สีอย่างเดียวสื่อความหมาย (มีไอคอน/ข้อความ ✓ ✕ ⚠ กำกับ), `prefers-reduced-motion`
- **ยังไม่ได้ทำ:** ทดสอบกับ screen reader จริง (VoiceOver/TalkBack) — งานค้างตัวหนึ่ง

## 4. ฟังก์ชันฝั่งผู้ใช้ (ทีละหน้า)

> รูปแบบที่ใช้ในแต่ละหัวข้อ: **เส้นทาง · สิทธิ์เข้า · ทำอะไร · UX · ข้อมูล · ข้อควรระวัง/จุดเรียนรู้**
> ทุกหน้าเปิดได้โดยไม่ต้องล็อกอิน **เว้นแต่ระบุว่า "ต้องล็อกอิน"** ทุกหน้ามี `generateMetadata`/hreflang สำหรับ SEO (`src/lib/seo.ts`)

### 4.1 หน้าแรก `/` — `src/app/page.tsx`
- **ทำอะไร:** ทางเข้าหลัก เป็นกริดการ์ดเมนูทั้งหมดของผู้เดินทางที่ผู้ชมคนนั้นเห็น
- **องค์ประกอบ (บนลงล่าง):**
  1. ข้อความ "บัญชีถูกลบแล้ว" (เฉพาะเพิ่งลบบัญชี `?erased=1`)
  2. **การ์ดทักทาย** (`GreetingCard`): โลโก้ + "สวัสดี, <ชื่อ>" (หรือ "สวัสดี") + คำถาม "พร้อมไปเมืองไทยหรือยัง?" บนฮีโร่ภาพประกอบธีมไทย มีผ้าคลุมขาวไล่จางให้ตัวอักษรอ่านง่าย
  3. **แบนเนอร์ข่าวปักหมุด** (โทนเขียวอ่อน): ข่าวที่ปักหมุดและเผยแพร่ **ล่าสุดข่าวเดียว** หัวข้อ ≤ 2 บรรทัด เนื้อหา ≤ 3 บรรทัดตามความกว้างจอ (ตัด `line-clamp`; อย่าใส่คลาส `block` คู่กัน มันทับ `display` ของ clamp) + ลิงก์ "อ่านข่าวทั้งหมด →" แอดมินไม่เห็นแบนเนอร์
  4. **แบนเนอร์เชิญเข้าสู่ระบบ** (เฉพาะผู้เยี่ยมชม): ข้อความ + ปุ่มเข้าสู่ระบบ
  5. **ส่วน "ผู้เดินทาง"**: การ์ดจาก `NAV` (`home: true`, `area: traveler`) กรองตามสิทธิ์/flag ผู้เยี่ยมชมไม่เห็นการ์ด "การแจ้งเตือน" และ "บัญชี"
  6. **ส่วน "หลังบ้าน"** (เฉพาะเจ้าหน้าที่): การ์ดของพื้นที่ที่บทบาทมีสิทธิ์
- **UX:** การ์ดเรียงด้วย `packCards` (ไม่มีการ์ดครึ่งแถวโดดเดี่ยว) และสีด้วย `spreadTones` (ดู 3.10) การ์ดที่ต้องล็อกอินมีกุญแจ
- **เจ้าหน้าที่:** หน้าแรกคือ `/admin` (การ์ดทักทาย + การ์ดหลังบ้าน) โลโก้ที่หัวพาไป `/admin`

### 4.2 เข้าสู่ระบบ `/login`
- **ทำอะไร:** เข้าสู่ระบบ/สมัคร/ลืมรหัสผ่านในหน้าเดียวสลับโหมด (`signin` | `signup` | `forgot`)
- **วิธี:** อีเมล+รหัสผ่าน (ขั้นต่ำ 8 ตัว ต้องกรอกซ้ำตอนสมัคร), ปุ่ม **Google** (ไอคอน G หลายสีตามแบรนด์ Google), ปุ่ม **LINE** (เปลี่ยนเส้นทางไปศูนย์ SSO ภายนอก `…/sso/authorize?app=<slug>&return=<callback>` แล้วกลับที่ `/sso/callback`) เปิด/ปิดแต่ละวิธีได้ด้วย flag
- **UX:** ข้อความแสดงใต้ฟอร์ม; อีเมลตรวจรูปแบบก่อนส่ง; ล้างรหัสผ่านเมื่อสลับโหมด; ปุ่ม Google/LINE ค้าง spinner จนเบราว์เซอร์ออกจากหน้า (ไม่ให้กดซ้ำ); หลังสำเร็จ **นำทางแบบ hard navigation** ไป `next` (ผ่าน `safeNext`); ข้อความท้าย "การดำเนินการต่อถือว่ายอมรับข้อกำหนดและนโยบายความเป็นส่วนตัว"
- **ลืมรหัสผ่าน:** ส่งลิงก์ไป `/auth/callback?next=/account/password` ให้ตั้งรหัสใหม่ที่หน้า `/account/password`
- **ข้อควรระวัง:** สมัครอีเมลซ้ำ Supabase ไม่บอกตรง ๆ โค้ดลองล็อกอินทันที ถ้าไม่ผ่านจึงแจ้ง "อีเมลนี้มีบัญชีแล้ว"

### 4.3 บัญชี `/account` · `/account/notifications` · `/account/password` · `/account/privacy` — ต้องล็อกอิน
| หน้า | ทำอะไร | UX/รายละเอียด |

### 4.4 การแจ้งเตือนในแอป `/notifications` — ต้องล็อกอิน
- **ทำอะไร:** รายการแจ้งเตือนของฉัน (สถานะ ชำระเงิน คืนเงิน เตือนเวลา ฯลฯ) เรียงใหม่สุดก่อน ปุ่ม **"อ่านทั้งหมดแล้ว"**
- **UX:** แถวที่ยังไม่อ่านเด่นกว่า; **กดแถว = ทำเครื่องหมายอ่านแล้วและไปยังเรื่องนั้น**; กระดิ่งมุมขวาบนมีจำนวนที่ยังไม่อ่าน (อัปเดตสดด้วย live sync); ข้อความว่าง "ยังไม่มี การอัปเดตจะแสดงที่นี่"
- **ข้อมูล:** `app_notifications` (user_id, title, body, link, kind, dedupe_key, read_at) การแทรกแถวทำให้เกิด ping live sync (database trigger) `dedupe_key` กันแจ้งซ้ำเมื่อโค้ดรันซ้ำ

### 4.4a สมุดผู้เดินทาง `/travelers` — ต้องล็อกอิน
- **ทำอะไร:** รายชื่อผู้ที่เคยยื่นแทน (ชื่อ, สัญชาติ, พาสปอร์ตเลขท้าย 4 ตัว, วันหมดอายุ) เพื่อใช้ซ้ำในทริปใหม่
- **UX:** ป้ายเตือนเมื่อพาสปอร์ตจะหมดอายุภายใน 6 เดือน; ปุ่ม "ใช้สำหรับทริปใหม่" และ "ลบ" (ลบไม่ได้ถ้ากำลังอยู่ในใบสมัคร)
- (การสร้างผู้เดินทางเกิดในขั้นตอนยื่นขอ ซึ่งเป็นแกนของโดเมนเดิม)

### 4.5 บริการเสริม `/extras`
- **ทำอะไร:** แคตตาล็อกบริการเสริม (ประกัน, eSIM, ซิมรับที่สนามบิน, VIP, ความงามและสุขภาพ) แสดงเฉพาะที่พาร์ทเนอร์เชื่อมแล้ว มีข้อความ "ไม่มีให้กับแพ็กเกจ Express" ตามกฎ; ถ้ายังไม่มีพาร์ทเนอร์ แสดง "จะปรากฏเมื่อเชื่อมพาร์ทเนอร์"
- **ที่มา:** `partner_packages` (ซิงก์จาก API พาร์ทเนอร์หรือที่พาร์ทเนอร์ลงเอง) การสั่งซื้อทำในขั้นตอนที่ 3 ของการยื่นขอ (แกนของโดเมนเดิม) ดังนั้นหน้านี้เป็น **ข้อมูลและปุ่มพาไปยื่นขอ**

### 4.6 ช่วยเหลือ `/help` · ผู้ช่วย AI `/help/chat`
- **`/help`:** ศูนย์ช่วยเหลือ: **ช่องค้นหา** คำถามที่พบบ่อย (ค้นในคำถามและคำตอบ) แต่ละข้อ **กางออก/พับได้โดยไม่ออกจากหน้า** (`<details>`) + ทางลัดการ์ด: ถามผู้ช่วย, ตรวจใบสมัคร, ช่องทางทางการ, สิ่งที่ต้องเตรียม, คู่มือสนามบิน, ข่าว, บทความ
- **ที่มา FAQ:** คำถามที่เขียนในหลังบ้าน (`content_items` kind `faq`) ถ้ามี ไม่เช่นนั้นใช้ชุดในโค้ด (fail open)
- **`/help/chat` (ผู้ช่วย AI):** แชตที่ตอบจากข้อมูลของระบบ: ราคา, ข้อกำหนด, ข่าว/บทความที่เผยแพร่, FAQ, ช่องทางทางการ และ (ถ้าล็อกอิน) ใบสมัครของผู้ใช้เอง มีคำถามแนะนำ 3 ข้อให้แตะ; **บทสนทนาอยู่ในหน้านั้นเท่านั้นไม่บันทึก** ส่ง 10 ข้อความล่าสุดไปกับทุกคำถาม; ข้อความยาวสุด 2,000 ตัวอักษร; เมื่อ AI ปฏิเสธ/นอกขอบเขต แสดงข้อความมาตรฐาน; มีงบรายวัน/ต่อผู้ใช้ (หัวข้อ 6.2) หน้านี้ **ไม่ถูก live sync รีเฟรชเอง**

### 4.7 คู่มือสนามบิน `/guide` และสิ่งที่ต้องเตรียม `/prepare`
- **`/guide`:** ขั้นตอนหลังลงเครื่องเป็นรายการเลขลำดับ + รายชื่อสนามบิน (แต่ละแห่งมีหมายเหตุ เคาน์เตอร์/ช่อง/เวลา) หมายเหตุเฉพาะสนามบินแก้ได้จากหลังบ้าน `/admin/airports` (`airport_notes`) ท้ายหน้ากล่องเตือนว่าให้ตรวจกับสนามบิน
- **`/prepare`:** เช็กลิสต์เอกสารที่ต้องมี (หนังสือเดินทาง ตั๋ว ที่พัก หลักฐานการเงิน) เป็นรายการลำดับ + ปุ่มทองพาไปยื่นขอ
- เนื้อหามีครบ EN/TH/ZH-CN (`content/guide.ts`) ภาษาอื่นตกกลับ EN

### 4.8 ช่องทางทางการ `/official` — `src/app/official/page.tsx`
- **ทำอะไร:** บอกว่า "ช่องทางไหนคือเราจริง" และวิธีเลี่ยงเว็บปลอม: เว็บของเรา, เว็บทางการอื่น, **LINE**, **อีเมล**, **โทรศัพท์**, เวลาให้บริการ + กล่องคำเตือน 4 ข้อ
- **UX ที่ทำให้ใช้ได้ทันที:** แตะ **LINE ID** → เปิดหน้า "เพิ่มเพื่อน" ของ LINE ในแท็บใหม่ (`@id` → `https://line.me/R/ti/p/%40id`, ID ส่วนตัว → `https://line.me/ti/p/~id`); แตะ **เบอร์โทร** → เริ่มโทร (`tel:+66…` ตัดช่องว่าง/ขีด/วงเล็บ); แตะ **อีเมล** → `mailto:` ข้อความที่ไม่เข้ารูป LINE ID/เบอร์ถูกต้อง แสดงเป็นข้อความธรรมดา (ไม่สร้างลิงก์) (`src/lib/channel-links.ts` พร้อมเทสต์)
- **ข้อมูล:** ตั้งค่าที่ `/admin/channels` → `platform_settings.official_channels` เก็บเฉพาะข้อความธรรมดา + ลิงก์ https ที่ผ่านการตรวจ (เพราะแสดงต่อทุกคน)

### 4.9 หน้ากฎหมาย `/privacy` · `/terms` (`LegalPage`)
- โครงเนื้อหาหลายหัวข้อ (`content/legal.ts`) ครบ EN/TH/ZH-CN ใช้ข้อความร่าง ต้องให้ที่ปรึกษากฎหมายตรวจก่อนใช้จริง ตัวแปรชื่อแบรนด์/บริษัท/อีเมลดึงจากการตั้งค่า (`/admin/company`, แบรนด์)

### 4.10 ข่าว `/news` และบทความท่องเที่ยว `/articles` · `/articles/<slug>`
- **ข่าว:** รายการข่าวที่เผยแพร่ใหม่สุดก่อน (การ์ดขาว หัวข้อ วันที่ เนื้อหา) เนื้อหาเป็น **rich text** (หัวข้อย่อย ตัวหนา/เอียง ลิสต์ กล่องหมายเหตุ ลิงก์ รูปภาพ) แสดงผ่านตัวเรนเดอร์ที่ปลอดภัย (ไม่ใช้ HTML ดิบ) ข่าวเก่าแบบข้อความล้วนยังแสดงปกติ (คงการขึ้นบรรทัด)
- **บทความ:** รายการ + หน้าบทความ (`ArticleView`) มีหัวข้อย่อย ท้ายบทความปุ่มพาไปยื่นขอ; **slug ถาวร** (สร้างแล้วไม่เปลี่ยน) อยู่ใน sitemap; บทความในโค้ดเป็นค่าเริ่มต้น เมื่อเผยแพร่บทความจากหลังบ้านอย่างน้อยหนึ่งบทความ ระบบใช้ชุดจากหลังบ้านแทน
- **ภาษา:** แสดงภาษาของผู้อ่านถ้ามี ไม่มีใช้อังกฤษ **AI ผู้ช่วยอ่านข่าว/บทความที่เผยแพร่** (เป็นข้อมูลอ้างอิง ไม่ใช่คำสั่ง)

### 4.11 ชุดเครื่องมือ "ระหว่างอยู่ในไทย" `/toolkit`
หน้ารวมเป็นกริดการ์ด (ลิงก์ `NavRowLink`) ไป 10 เครื่องมือ: อากาศและฝุ่นตอนนี้, Stay Guard, บัตรเข้าเมือง TDAC, เช็กกฎ, เมื่อเกิดเหตุ, เช่ายานพาหนะ, เช็กอินครอบครัว, ตู้เอกสารออฟไลน์+บัตรสุขภาพ, บัตรวลีภาษาไทย, ฉุกเฉิน — ทุกเครื่องมือ **ใช้ได้โดยไม่ต้องล็อกอิน** ยกเว้นเช็กอินครอบครัว และส่วนผูกกับทริป/แจ้งเตือนตามสถานที่

**4.11.1 เบอร์ฉุกเฉิน `/emergency`**
- รายการเบอร์ (1155 ตำรวจท่องเที่ยว, 191, 1669, 199, 1672 ททท., 1178 ตม.) แต่ละเบอร์เป็นปุ่มโทร `tel:` ใหญ่สีแดง "โทร <เบอร์>" + คำอธิบายการใช้
- **บัตรวลีด่วน** (6 วลีเร่งด่วน) + ลิงก์ไปวลีทั้งหมด
- **"แบ่งปันตำแหน่ง" (`LocationBox`):** ปุ่มขอตำแหน่งจากเบราว์เซอร์ แสดงพิกัดบนหน้าจอเพื่ออ่านให้เจ้าหน้าที่/คัดลอก **ไม่ส่งไปเซิร์ฟเวอร์ ไม่เก็บ**
- ลิงก์ **"เปิดสำเนาออฟไลน์"** (`/offline-emergency.html` ไฟล์ static ไม่มีข้อมูลส่วนตัว ถูกแคชโดย service worker เปิดได้โดยไม่มีเน็ต) มีเทสต์ว่าหน้าออฟไลน์ตรงกับหน้าปกติ
- เนื้อหา (เบอร์/คำอธิบาย/วลี) แก้ได้จากหลังบ้านที่ `/admin/toolkit` (ค่าในโค้ดเป็นสำรอง)

**4.11.2 บัตรวลีภาษาไทย `/phrases`** — `PhraseCard`
- รายการวลีแยก "ด่วน" และ "ประจำวัน" แต่ละวลีแสดง ภาษาไทย + คำอ่านโรมัน + ความหมายในภาษาผู้ใช้ **แตะวลี → เต็มจอ** ตัวไทยใหญ่ให้คู่สนทนาอ่าน ปุ่ม "ปิด" (โฟกัสอัตโนมัติ) ใช้ได้ 9 ภาษา

**4.11.3 เช็กกฎ `/check-rules`** — รายการสิ่งที่นักท่องเที่ยวมักผิด (บุหรี่ไฟฟ้า, ยาเสพติด, กัญชา, แอลกอฮอล์, สูบบุหรี่ที่หาด, โดรน, สถาบันพระมหากษัตริย์, วัด, ถ่ายภาพ, มอเตอร์ไซค์, เช่ารถ, เงินสดที่ด่าน) ติดป้ายระดับ **ห้าม / มีข้อจำกัด / แสดงความเคารพ / ระวัง** พร้อมวันที่ตรวจทานล่าสุดและข้อความ "ไม่ใช่คำแนะนำทางกฎหมาย"

**4.11.4 Stay Guard `/stay`** — ตัวนับวันพำนัก
- แสดง "ทริปที่ได้รับอนุมัติ" ของผู้ใช้ (ล็อกอินแล้ว) พร้อมนับถอยหลังจากวันถึง (นับวันถึงเป็นวันที่ 1); ผู้ใช้ที่ยังไม่ล็อกอินเห็นข้อความเชิญล็อกอิน และใช้ **เครื่องคำนวณ** (`StayCalculator`: ใส่วันถึง + จำนวนวันที่อนุญาต → วันสุดท้าย) ได้ทันที
- **เตือนล่วงหน้า 7, 3, 1 วัน** ก่อนครบ (งานอัตโนมัติ หัวข้อ 6.4) ผ่านทุกช่องทาง
- ข้อความอธิบาย: ประมาณการจากวันถึงในใบสมัคร **ตราประทับที่เจ้าหน้าที่ประทับคือที่ยึดจริง**, วิธีต่ออายุ, โทษของการอยู่เกิน
- (ข้อมูลทริปมาจากแกนของโดเมนเดิม; เครื่องมือนี้เป็นส่วนเสริม)

**4.11.5 บัตรเข้าเมือง TDAC `/tdac`** — ตัวช่วยฟรี
- อธิบาย: ต้องกรอกออนไลน์ภายใน 3 วันก่อนถึง ฟรี แยกจากวีซ่า ขั้นตอน ข้อควรระวังเว็บปลอม; ปุ่ม **เปิดเว็บ TDAC ทางการ** (`OutLink` เปิดแท็บใหม่) ถ้าผู้ใช้มีทริปที่อนุมัติ แสดง "ทริปของคุณ: ถึงวันที่ … กรอกได้ตั้งแต่ … ถึง …"

**4.11.6 อากาศและฝุ่นตอนนี้ `/conditions`** — ที่ปรึกษาความปลอดภัย
- เลือกสถานที่ (`PlacePicker`: จังหวัด/เมืองท่องเที่ยวที่มีข้อมูล) แล้วเห็น: อุณหภูมิ/รู้สึกเหมือน, ความชื้น, ลม, สูงสุดวันนี้, โอกาสฝน, ดัชนี UV, **PM2.5** (วัดจริงจากสถานี Air4Thai ที่ใกล้สุดภายใน 40 กม. และอ่านไม่เกิน 4 ชม. มิฉะนั้นเป็นค่าประมาณและบอกชัดว่าเป็นค่าประมาณ), **คำแนะนำว่าควรทำอย่างไร** (อากาศร้อน/ฝน/พายุ/UV/ฝุ่น เป็นคำพูดชัด), **คำเตือนทางการของกรมอุตุนิยมวิทยา (CAP)** ที่มีผลกับจังหวัดนั้น (แสดงเป็นภาษาไทยตามที่ประกาศ)
- **ติดตามสถานที่ (`WatchBox`, ล็อกอิน):** ติดตามได้ถึง 5 แห่ง เมื่อมีคำเตือนทางการระดับปานกลาง/รุนแรงของจังหวัด ระบบแจ้งเตือน (Push/LINE/ในแอป ไม่ใช่อีเมล) ครั้งเดียวต่อคนต่อคำเตือน (ตรวจทุก 30 นาที)
- ปุ่ม **"ถามผู้ช่วยเรื่องนี้"** (AI มีเครื่องมือ `get_conditions` อ่านข้อมูลชุดเดียวกัน ถ้าไม่มีข้อมูลต้องบอกว่าไม่มี ห้ามเดา)
- **ข้อมูลล่ม:** ถ้า Open-Meteo/แหล่งอื่นเข้าไม่ได้ แสดง "ตอนนี้ยังไม่มีข้อมูลสด ลองใหม่ภายในไม่กี่นาที" ไม่แสดงตัวเลขเดา ผลลัพธ์แคช 10 นาที ท้ายหน้ามีเครดิตแหล่งข้อมูล (Open-Meteo)
- **ข้อควรระวัง:** Open-Meteo ฟรีมีโควต้าต่อ IP (เคยเจอ 429) ใช้งานจริงต้องมีแผนเสียเงิน/`OPEN_METEO_API_KEY`

**4.11.7 เมื่อเกิดเหตุ `/incident` · `/incident/<slug>`**
- เลือกสถานการณ์ (8 เรื่อง: อุบัติเหตุถนน/มอเตอร์ไซค์, เจ็บป่วยรุนแรง, พาสปอร์ตหาย, โทรศัพท์/กระเป๋า/บัตรหาย, ถูกลักทรัพย์/ปล้น, ถูกหลอก/เรียกเงินเกิน, ถูกเรียกตรวจ/จับกุม, น้ำท่วม/พายุ/แผ่นดินไหว) → หน้าเรื่องนั้นให้ **"โทรก่อน"** (ปุ่มเบอร์ที่เกี่ยวข้อง) แล้ว **"ทำอะไรตามลำดับ"** เป็นข้อ ๆ (6 ขั้น) ลิงก์ไป เบอร์ฉุกเฉิน, อากาศ, ตัวช่วยเช่ายานพาหนะ, ใบสมัครของฉัน; ท้ายหน้า "ไม่ใช่คำแนะนำทางกฎหมาย/การแพทย์"
- แก้เนื้อหาได้จากหลังบ้าน (`/admin/toolkit` ชนิด incidents)

**4.11.8 ตัวช่วยเช่ายานพาหนะ `/rental`** — `RentalHelper`
- **เช็กลิสต์ 4 กลุ่ม** (ก่อนเช่า, ตอนรับรถ, ระหว่างขับขี่, ตอนคืน) ติ๊กได้ แสดงความคืบหน้า "ทำแล้ว X จาก 15"
- **ตัวช่วยถ่ายรูป:** 8 ช่อง (หน้า หลัง ซ้าย ขวา ป้ายทะเบียน น้ำมัน/เลขไมล์ ความเสียหาย 1–2) ถ่ายด้วยกล้อง **ประทับวันเวลา + สถานที่ (ถ้าอนุญาต) ลงบนรูป** (`lib/photo-stamp.ts`) รูปอยู่ในเครื่อง **ไม่ส่งขึ้นเซิร์ฟเวอร์** ดาวน์โหลด/แชร์เก็บเป็นหลักฐาน

**4.11.9 ตู้เอกสารออฟไลน์และบัตรสุขภาพ `/offline-vault.html`** (route handler ไดนามิก ไม่ใช่หน้า React)
- เก็บ **เอกสาร (รูป/PDF/โน้ต)** และ **บัตรสุขภาพสองภาษา (อังกฤษ+ไทย)** ไว้ **ในมือถือเท่านั้น** (IndexedDB) เข้ารหัสด้วย **รหัสผ่านที่ผู้ใช้ตั้ง** (PBKDF2 250,000 รอบ + AES-256-GCM, WebCrypto) — เราไม่เห็นเนื้อหา จึงไม่เก็บข้อมูลสุขภาพ
- **ล็อกอัตโนมัติ** เมื่อไม่ใช้งาน, ปุ่มลบทั้งหมด, เปิดได้โดยไม่มีเน็ต (service worker แคชหน้าไว้หลังเปิดครั้งแรก) UI เป็นสคริปต์ JS ที่สร้างจาก source string (`lib/vault/crypto-src.ts`, `ui-src.ts`) แปลครบ 9 ภาษา (รวม RTL)
- **ข้อควรระวัง:** ลืมรหัสผ่าน = เปิดไม่ได้ (ไม่มีทางกู้) ต้องบอกผู้ใช้ชัด; ทดสอบบนมือถือจริงยังค้าง

**4.11.10 เช็กอินครอบครัว `/family`** — ต้องล็อกอิน (หน้าของผู้ติดต่อ `/family/<token>` ไม่ต้องมีบัญชี)
- **ผู้เดินทาง:** ปุ่ม **"ฉันปลอดภัย"** และ **"ฉันต้องการความช่วยเหลือ"** (ยืนยันก่อนส่ง มีตัวเลือก "ใส่ตำแหน่งของฉันในข้อความ ~100 ม."); **ผู้ติดต่อ** สูงสุด 5 คน เชิญทางอีเมลพร้อม **ลิงก์ลับ** (เก็บเฉพาะแฮชของโทเค็น แสดงลิงก์ครั้งเดียวถ้าไม่ได้ตั้งอีเมล) แต่ละคนต้อง **ตอบรับ** ก่อนจึงจะได้รับแจ้ง; **ตารางเช็กอิน** (ทุก 6/12/24/48 ชม., เวลารอ 1–12 ชม., วันสิ้นสุดทริป): ถึงเวลาเตือนผู้เดินทางก่อน ถ้าเลยเวลารอยังไม่เช็กอิน ผู้ติดต่อที่ตอบรับได้อีเมลหนึ่งฉบับต่อรอบ; เช็กอิน "ปลอดภัย" หลังเคยส่งแจ้งเตือน → ผู้ติดต่อได้อีเมล "ปลอดภัยแล้ว"; ประวัติเช็กอินล่าสุด 10 ครั้ง
- **หน้าผู้ติดต่อ (`/family/<token>`):** ตอบรับ/ปฏิเสธ, เห็นเวลาเช็กอินล่าสุดและสถานะ (ปลอดภัย/ขอความช่วยเหลือ), เตือนถ้าเลยกำหนด, ปุ่ม "เลิกรับแจ้ง", ข้อความแนะนำให้โทรหาผู้เดินทางก่อน แล้วโทรตำรวจท่องเที่ยว 1155/191 และสถานทูต; **ลิงก์หมดอายุหลังสิ้นสุดทริป 7 วัน**
- **ความเป็นส่วนตัวโดยออกแบบ:** ตำแหน่งเก็บ **เฉพาะ** เมื่อกด "ต้องการความช่วยเหลือ" และติ๊กใส่ตำแหน่ง ปัดเศษ ~100 ม.; ผู้ติดต่อเห็นแค่ชื่อต้น เวลา และสถานะ; ข้อมูลเช็กอินเก็บ 30 วัน; ลบบัญชี/ส่งออกข้อมูลครอบคลุม; อ่านเขียนผ่านเซิร์ฟเวอร์เท่านั้น (RLS ปิดทุกตาราง)
- **ข้อควรระวัง:** ฟีเจอร์นี้ไม่ได้เรียกตำรวจให้ (ข้อความบอกชัด); แจ้งเตือนผู้เดินทางส่งในแอป/Push/LINE ไม่ส่งอีเมล (กันสแปม)

### 4.12 ลิงก์จ่ายแทน `/pay/link/<token>` — สาธารณะ (ไม่ต้องล็อกอิน)
- **ทำอะไร:** เจ้าของทริปสร้างลิงก์ให้คนอื่น (เช่น พ่อแม่/บริษัท) จ่ายเงินแทน ผู้จ่ายเห็นสรุป (ชื่อผู้เดินทาง วันถึง ยอดรวม) กด **"ชำระเงินเลย"** ไป Stripe; ผู้เดินทางได้ใบเสร็จและการแจ้งเตือนทั้งหมดเหมือนเดิม
- **ความปลอดภัย:** โทเค็นลิงก์ยาว เก็บ **เฉพาะแฮช**; หมดอายุ; ใช้ครั้งเดียว (จ่ายแล้วแสดง "ชำระแล้ว ขอบคุณ"); ลิงก์ไม่ถูกต้อง/หมดอายุ → ข้อความกลาง ๆ; สร้างได้ ≤ 10 ลิงก์/ชั่วโมง/ผู้ใช้ (rate limit)
- **จุดเรียนรู้:** แนวทาง "ลิงก์ลับที่เก็บแฮช + ตอบรับ + หมดอายุ" ใช้ซ้ำได้กับ เชิญเพื่อนร่วมทริป, แชร์แพ็กเกจให้ลูกค้า ฯลฯ

### 4.13 หน้า "กำลังจะมา" `/soon/<key>`
เมนูที่ `status: "soon"` ชี้มาที่นี่: ข้อความ "ส่วนนี้กำลังสร้าง จะปรากฏเร็ว ๆ นี้" + "วางแผนใน <Phase>" + ปุ่มกลับหน้าแรก

## 5. ฟังก์ชันของเอเจนซี่ พาร์ทเนอร์ ภาครัฐ และหลังบ้าน

### 5.1 พอร์ทัลเอเจนซี่ `/agency` · `/agency/team` · `/agency/import` — ต้องล็อกอิน
- **สมัคร:** ฟอร์มลงทะเบียนเอเจนซี่ (ชื่อบริษัท ผู้ติดต่อ อีเมล มือถือ ประเทศ เลขใบอนุญาต(ไม่บังคับ) **ไฟล์เอกสารจดทะเบียน**) → สถานะ "รออนุมัติ" ทีมงานตรวจก่อนจึงยื่นแทนลูกค้าได้ (แจ้งเตือนเมื่ออนุมัติ) ตัวเลขประโยชน์ที่แสดงก่อนสมัคร: ยื่นแทนลูกค้าจำนวนมากและจ่ายครั้งเดียวต่อทริป, ส่วนลดค่าบริการ + คอมมิชชัน, เพิ่มทีมและนำเข้าจากสเปรดชีต
- **ภาพรวมเอเจนซี่ที่อนุมัติแล้ว:** ใบสมัครเดือนนี้ที่ชำระแล้ว, คอมมิชชันสะสม, ลิงก์ไปทีม/นำเข้า, **ใบแจ้งหนี้/สรุปรายเดือน** (PDF และ CSV, ไทย/อังกฤษ) + สถานะจ่ายคอมมิชชัน (`ExportLink` ดาวน์โหลดไฟล์)
- **ทีม `/agency/team`:** เจ้าของเอเจนซี่เพิ่ม/ลบสมาชิก (บทบาท Owner/Agent) ด้วยอีเมลของคนที่ **เคยล็อกอินเว็บนี้แล้วครั้งหนึ่ง** (ต้องมีบัญชีอยู่)
- **นำเข้า CSV `/agency/import`:** นำเข้าผู้เดินทางสูงสุด 200 คนต่อไฟล์ มีไฟล์แม่แบบให้ดาวน์โหลด ระบุคอลัมน์ (เพศ M/F, สัญชาติรหัส 3 ตัว, รูปแบบวันที่) หรือวางแถวลงช่องข้อความ แสดงผลนำเข้าสำเร็จ/ข้ามพร้อมเหตุผลต่อแถว
- **หลังบ้านเอเจนซี่ `/admin/agencies` (สิทธิ์ finance):** อนุมัติ/ระงับ, ตั้ง **ส่วนลดค่าบริการต่อใบสมัคร (บาท)**, **% คอมมิชชันจากค่าบริการ**, บันทึกภายใน, ดูเอกสาร, ดู **ใบแจ้งหนี้รายเดือน** (PDF/CSV), กด **"บันทึกว่าจ่ายคอมมิชชันแล้ว"** พร้อมหมายเหตุอ้างอิงโอน (`agency_payouts`)
- **จุดเรียนรู้:** โมเดลตัวแทนขาย (agency) ใช้ซ้ำได้กับ "ตัวแทนทัวร์/โรงแรม" โดยเปลี่ยนสินค้า

### 5.2 พอร์ทัลพาร์ทเนอร์ `/partner` — ต้องล็อกอิน
- **สมัคร:** ชนิดสินค้า (SIM/eSIM, VIP สนามบิน, ความงามและสุขภาพ, ประกัน) + ข้อมูลบริษัท → รออนุมัติ
- **จัดการแพ็กเกจเอง:** ชื่อ ราคา คำอธิบาย **จำนวนคงเหลือ (stock limit)** เปิด/ปิดขาย → ผู้เดินทางเห็นและซื้อใน `/extras`/ขั้นตอนยื่นขอ
- **voucher:** ผู้ซื้อได้ **โค้ดบัตรกำนัล** พาร์ทเนอร์กรอกโค้ดที่เคาน์เตอร์เพื่อ **redeem** (ใช้สิทธิ์ครั้งเดียว บันทึกวันเวลา) → ผู้เดินทางได้แจ้งเตือน "ใช้บริการแล้ว"
- **ยกเลิก voucher (`VoidVoucher`):** พาร์ทเนอร์ยกเลิกใบที่ยังไม่ใช้ → **คืนเงินเต็มให้ผู้เดินทางอัตโนมัติ** + แจ้งผู้เดินทาง
- **สรุปรายเดือน (settlement) CSV:** ยอดขาย ส่วนแบ่งพาร์ทเนอร์ (% ตั้งโดยแอดมิน) ยอดที่ต้องจ่าย
- **ทีมพาร์ทเนอร์:** เพิ่ม/ลบสมาชิก
- **แจ้งเตือนพาร์ทเนอร์:** ผ่านอีเมลเมื่อมีคำสั่งซื้อ/ยกเลิก
- **หลังบ้านพาร์ทเนอร์ `/admin/partners` (สิทธิ์ config):** อนุมัติ/ระงับ, **% ส่วนแบ่ง**, โหมด "จัดการในพอร์ทัล (ไม่มี API)" หรือเชื่อม API, ดู voucher ที่รอใช้/ใช้แล้วเดือนนี้/มูลค่าขาย, บันทึกการจ่ายเงินพาร์ทเนอร์รายเดือน (`partner_settlements`)
- **การเชื่อมพาร์ทเนอร์ผ่าน API:** ใช้ชั้นแปลง (adapter) ต่อประเภท; ซิงก์แคตตาล็อกเข้า `partner_packages` ทุก ~20 ชม. (งาน `partner_packages`); มี **ตัวจำลองพาร์ทเนอร์** `tools/mock-partners` สำหรับทดสอบก่อนต่อจริง (ดูหัวข้อ 8)

### 5.3 สถิติภาครัฐ/ททท. `/gov` (บัญชีอ่านอย่างเดียว) และ `/admin/tourism`
- **`/gov`:** หน้าสถิติ **ไม่ระบุตัวตน** (ตัวเลขรวม) ของผู้เดินทางที่ได้รับอนุมัติ: จำนวนตามวัน, สัญชาติ, สนามบิน, วัตถุประสงค์, เพศ, ช่วงอายุ + ส่งออก CSV; ไม่มีข้อมูลระบุตัวบุคคล
- **เมนูลัด** เฉพาะบัญชีผู้ดูรายงาน (`viewerOnly`) บัญชีนี้เข้าหลังบ้านอื่นไม่ได้
- **`/admin/tourism`:** หน้าเดียวกัน + จัดการบัญชีผู้ดูรายงาน (เพิ่ม/ลบด้วยอีเมลของบัญชีที่มีอยู่) (`report_viewers`)

## 6. บริการเบื้องหลัง

### 6.1 การแจ้งเตือนหลายช่องทาง — `src/lib/notify.ts`, `lib/messaging/*`, `lib/push/*`, `lib/mailer.ts`
**จุดเดียวที่ใช้ส่ง:** `notifyUser({ userId, title, body, link, kind, dedupeKey, mail?, fields?, note? })` ไม่ throw
1. **ในแอป:** แทรก `app_notifications` (ถ้า `dedupe_key` ซ้ำ = เหตุการณ์เดิม ไม่ส่งต่อทุกช่องอีก) การแทรกปลุกหน้าที่เปิดอยู่ผ่าน live sync
2. **อีเมล** (ยกเว้น `mail: false` และ `kind: "test"`; ข้ามถ้าผู้ใช้ปิดอีเมลแจ้งเตือน): ภาษาตามโปรไฟล์, ปุ่ม "เปิด" ลิงก์ไปหน้าในแอป, ท้ายอีเมลมีลิงก์จัดการ + `List-Unsubscribe`; ส่งผ่าน Resend HTTP API (`RESEND_API_URL` กำหนดเองได้เพื่อทดสอบ); บันทึกเฉพาะจำนวนกับรหัสตอบกลับ (`mail_log`)
3. **LINE:** การ์ด **Flex Message** — หัวสีตามชนิด (น้ำเงิน = ข้อมูล, เขียว = อนุมัติ, เหลืองอำพัน = ต้องทำ/ใกล้กำหนด, แดง = ปฏิเสธ/ล้มเหลว, เขียวน้ำทะเล = ชำระเงิน, ม่วง = คืนเงิน, ชมพู = บริการเสริม, กรมท่า = เจ้าหน้าที่) + แถว "ป้าย | ค่า" (เช่น เลขอ้างอิง/สถานะ) + หมายเหตุ + ปุ่ม "เปิดดู" ป้ายและปุ่มเป็นภาษาของผู้รับ; ถ้า LINE ปฏิเสธการ์ด (HTTP 400) **ส่งซ้ำเป็นข้อความธรรมดาทันที** ไม่เสียข้อความ/ไม่หยุดช่อง; เหตุผลปฏิเสธไม่ใส่ในการ์ด (กันขึ้นหน้าจอล็อก)
4. **WhatsApp:** ต้องใช้ **template ที่ Meta อนุมัติล่วงหน้า** (ธุรกิจเริ่มสนทนาได้เฉพาะแบบนี้) ตอนนี้ส่ง template เดียว (ตัวแปร 2 ตัว: หัวข้อ + เนื้อหา/ลิงก์) ภาษา template ตั้งด้วย `WHATSAPP_TEMPLATE_LANG` — การทำให้ใกล้เคียงการ์ดต้องเพิ่ม template แบบมีหัวรูป/ปุ่มลิงก์ และ template ต่อภาษา (ยังไม่ทำ; ยังไม่ทดสอบกับบัญชีจริง)
5. **Web Push:** `push_subscriptions` ต่อเบราว์เซอร์ (VAPID) ข้อความสั้นพร้อมลิงก์ SW แสดงการแจ้งเตือนและเปิดหน้าตามลิงก์
- **การผูกช่องทาง:** LINE = รหัสครั้งเดียว 8 ตัว (ไม่มี 0/O/1/I) ส่งให้บัญชีทางการ → webhook ผูก `userId` ของ LINE (หมดอายุ 30 นาที, ลองผิดได้ 5 ครั้ง); WhatsApp = ส่งรหัส 6 หลักเป็น template ไปยังเบอร์ (หมดอายุ 15 นาที, ผิดได้ 5 ครั้ง) ผูกแล้วสถานะ `active` ถ้าผู้ใช้บล็อกบัญชี/เลิกติดตาม → `stopped` (ผู้ใช้เชื่อมใหม่ได้)
- **โควต้า:** ต่อช่องต่อเดือน (`message_log` นับเฉพาะที่ส่งจริง); เมื่อเต็ม ช่องนั้นข้ามแต่ในแอป/อีเมลยังไป
- **ผู้รับแต่ละรายได้เฉพาะแจ้งสถานะ/ใบเสร็จ** ไม่ใช่การตลาด (ข้อความอธิบายชัดในหน้าตั้งค่า)

### 6.2 ผู้ช่วย AI — `src/lib/ai/*`, `/api/assistant`
- **ชั้น adapter หลายผู้ให้บริการ** (Claude, Gemini) เลือก **ผู้ให้บริการ + โมเดลต่องาน** จากหลังบ้าน มี **ตัวสำรอง** (สลับอัตโนมัติเมื่อหลักล้มเหลว และบันทึกประวัติการสลับ)
- **คำสั่งระบบ** (`prompt.ts`) ประกอบจาก: บทบาท/ขอบเขต (อธิบายและช่วยดูข้อมูล **ไม่ตัดสินการอนุมัติ**), ราคาและกติกาคืนเงินปัจจุบัน, ช่องทางทางการ, FAQ ที่เผยแพร่ (อังกฤษ), ข่าว 5 ข่าวล่าสุดและบทความ (**ข้อมูลอ้างอิง ไม่ใช่คำสั่ง** กัน prompt injection), ภาษาของผู้ใช้ + คำสั่งเพิ่มเติมจากแอดมิน (ผ่านการตรวจ)
- **เครื่องมือ (tool use):** `get_my_applications` (เฉพาะของผู้ใช้เอง ผ่านสิทธิ์ของเขา ชื่อผู้เดินทางเฉพาะชื่อต้น), `get_fees`, `check_eligibility`, `get_conditions` (อากาศ/ฝุ่น/คำเตือน) ผลลัพธ์เครื่องมือเป็นข้อความที่อ่านง่ายและตอบ "ไม่มีข้อมูล ห้ามเดา" เมื่อแหล่งล่ม
- **ควบคุมต้นทุน:** งบ token รายวันรวม, token สูงสุดต่อคำตอบ, rate limit ต่อผู้ใช้/ต่อผู้เยี่ยมชมต่อชั่วโมง; การใช้งานบันทึกเป็นตัวเลข (`ai_usage`, `ai_events`) ไม่เก็บบทสนทนา
- **ความปลอดภัย:** ไม่ส่งข้อมูลส่วนบุคคลเกินจำเป็น; ปฏิเสธเรื่องนอกขอบเขตด้วยข้อความมาตรฐาน; เปิด/ปิดได้ด้วย feature flag `ai_assistant`
- **การทดสอบ:** มี "ผู้ให้บริการจำลอง" (`ANTHROPIC_BASE_URL` ชี้ตัวจำลอง) ทดสอบกับระบบจริงโดยไม่เสียเงิน

### 6.3 ที่ปรึกษาความปลอดภัย (อากาศ ฝุ่น คำเตือน) — `src/lib/conditions/*`
- **แหล่งข้อมูล:** Open-Meteo (พยากรณ์+คุณภาพอากาศแบบจำลอง), **Air4Thai** (PM2.5 วัดจริงรายสถานี เรียกผ่าน HTTP เพราะใบรับรอง HTTPS ของปลายทางไม่ครบ; ตรวจช่วงค่าและอายุข้อมูล; `AIR4THAI_URL=off` ปิดได้), **กรมอุตุนิยมวิทยา (TMD)** คำเตือนแบบ CAP + ฟีด
- **กติกา:** PM2.5 ใช้ค่าที่วัดจริงถ้าสถานะอยู่ไม่เกิน 40 กม. และข้อมูลใหม่กว่า 4 ชม. มิฉะนั้นเป็นค่าประมาณและบอกผู้ใช้; แปลระดับเป็นคำแนะนำ (`ADVICE`) ที่เป็นภาษาธรรมดา 9 ภาษา; แคชผลลัพธ์ 10 นาที; ไม่มีข้อมูล = "ไม่มีข้อมูล" ห้ามแสดงตัวเลขเดา
- **การเตือนตามจังหวัด:** `warning_watches` (≤ 5 ที่ต่อคน) + งาน `warnings` ทุก 30 นาที → `notifyUser` (ไม่ส่งอีเมล)

### 6.4 งานตามเวลาและกฎอัตโนมัติ — `src/lib/jobs.ts`, `/api/cron/tick`, `src/lib/rules/*`
- **จุดเรียกเดียว:** `GET /api/cron/tick` (ต้องมี `Authorization: Bearer <CRON_SECRET>` เปรียบเทียบแบบ timing-safe) รันงานทีละตัว **แยกกัน** (ตัวหนึ่งล้มไม่หยุดตัวอื่น) และ **หยุดเริ่มงานใหม่เมื่อเกินงบเวลา 20 วินาที** (รายงานว่าหยุดที่ไหน) `?only=warnings,safety` รันเฉพาะงานที่ระบุ
- **ตัวกระตุ้น:** Vercel Cron วันละครั้ง (ขีดจำกัดของแผน Hobby) + **GitHub Actions ทุก 30 นาที** (`.github/workflows/warnings.yml`) เรียก `?only=warnings,safety` ต้องมี repository secrets `SITE_URL`, `CRON_SECRET` (ไม่มีก็ไม่ทำอะไร)
- **งานทั้งหมด:** `payments` (กระทบยอดการชำระ/หมดเวลาชำระ), `pre_check` (ตรวจซ้ำรายการที่รอ), `addons` (คิวบริการเสริม), `rules` (กฎอัตโนมัติ), `warnings` (คำเตือนทางการ), `safety` (เช็กอินครอบครัว: เตือน/แจ้งผู้ติดต่อ), `wallet` (อัปเดตบัตร Wallet), `reconcile` (รายงานกระทบยอดรายวัน), `partner_packages` (ซิงก์ถ้าเก่าเกิน 20 ชม.), `outbox` (ส่งออกไปหน่วยงานรัฐพร้อม retry), `poll` (ถามผลสำรอง), `master_sync` (ซิงก์รายการอ้างอิง), `housekeeping` (ล้าง `rate_limits` > 1 วัน, `error_log`/`mail_log`/`form_drafts` > 30 วัน, เช็กอินครอบครัว > 30 วัน), `purge` (ลบเอกสารหลังระยะเก็บ)
- **ทุกงาน idempotent:** รันซ้ำปลอดภัย (compare-and-set, `dedupe_key`)
- **กฎอัตโนมัติที่แอดมินปรับได้ (`/admin/rules`, `automation_rules`):** เตือนชำระ (หลังกี่ชั่วโมง ครั้งเดียว), **ปิดใบสมัครที่ค้างไม่ชำระ** (กี่วัน หรือเที่ยวบินลงจอดแล้ว), เตือนให้แก้ไข, **เตือนก่อนปิด** (กี่ชั่วโมงก่อน), เตือนเจ้าหน้าที่เมื่อใกล้เลย SLA, เตือนก่อนบิน, เตือน Stay Guard 7/3/1 วัน; แต่ละกฎ **ส่งครั้งเดียวต่อเหตุการณ์** (`automation_last_run`)

## 7. ข้อมูลและการตั้งค่า

### 7.1 หลักการฐานข้อมูล
- **Postgres (Supabase)** ไฟล์ `supabase/migrations/<timestamp>_<ชื่อ>.sql` เป็น **แบบเพิ่มอย่างเดียวและรันซ้ำได้** (`create table if not exists`, `add column if not exists`, `drop constraint if exists` ก่อนสร้างใหม่)
- **RLS เปิดทุกตาราง** ตารางที่ผู้ใช้อ่านของตัวเองผ่านเบราว์เซอร์มีนโยบาย `auth.uid() = owner_id`; ตารางความเป็นส่วนตัวสูง/ที่ระบบเขียนเอง **ไม่มีนโยบาย** (ปิดสนิท) เข้าถึงผ่านเซิร์ฟเวอร์ด้วย service role เท่านั้น (ตัวอย่าง: `safety_*`, `payment_links`, `push_subscriptions`)
- **ลบผู้ใช้ = cascade** (`references auth.users on delete cascade`) บวกขั้นตอนลบ/ทำให้ไม่ระบุตัวตนใน `lib/privacy/service.ts`
- **Storage (ถังไฟล์ส่วนตัว):** `documents` (ไฟล์เอกสารผู้ใช้ เข้ารหัสก่อนอัปโหลด จำกัด 5 MB) และ `brand-assets` (โลโก้/ไอคอน และโฟลเดอร์ `news/` สำหรับรูปข่าว) เสิร์ฟผ่านเส้นทางของเราเท่านั้น (`/brand/*`, `/news-img/*`) ไม่ใช้ลิงก์ public ของ Storage
- **หมายเหตุ Storage:** หลังลบไฟล์ การดาวน์โหลดที่เคยอ่านไว้อาจถูกแคชชั่วครู่ (เทสต์จึงเช็กการมีอยู่ด้วยการ list ไม่ใช่ download)
- **รันคำสั่ง SQL กับฐานข้อมูลจริง** ผ่าน Supabase Management API (`/v1/projects/<ref>/database/query`) ด้วย Personal Access Token ของเจ้าของ ต้องขออนุญาตทุกครั้งที่เขียน

### 7.3 `platform_settings` — คีย์ที่ใช้ (แก้จากหลังบ้านเกือบทั้งหมด)
`brand` (ชื่อ/โลโก้/ไอคอน), `company`, `fees`/`refund_policy`/`required_documents` (โดเมนเดิม), `official_channels`, `airport_notes`, `messaging` (เปิด/ปิดช่อง + โควต้า), `ai`, `ai_routing`, `ai_prompt_extra`, `audit_config`, `automation_rules`, `automation_last_run`, `feature_flags` (เฉพาะที่ **ปิด**), `toolkit_content` (เนื้อหาความปลอดภัยที่แก้), `eligibility`, `immigration_sim`, `addon_rules`
- **อ่านด้วย `getSetting(key, default)`** — ผ่านการตรวจรูปแบบ (parse แบบผ่อนปรน ค่าเสียก็ใช้ค่าเริ่มต้น) และแคชสั้น (`SETTINGS_TTL_MS`)
- **ลายเซ็นของ "เนื้อหาที่แก้ได้ + ค่าสำรองในโค้ด":** เนื้อหา (FAQ, บทความ, เบอร์ฉุกเฉิน, วลี, กฎ, คู่มือเมื่อเกิดเหตุ) มีชุดตั้งต้นในโค้ด ถ้าแอดมินยังไม่แก้ใช้ชุดโค้ด ถ้าแก้แล้วใช้ชุดที่แก้ (รายการว่าง = ถือว่าไม่ได้แก้) ฟอร์มแก้ล้างข้อมูลทุกรายการก่อนเก็บ (ตัดความยาว ตัดอักขระควบคุม ตรวจรูปแบบ) การอ่านที่พังจึงไม่ทำให้หน้าล้ม

- **Supabase:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (เปิดเผยได้), `SUPABASE_SERVICE_ROLE_KEY` (ลับ ฝั่งเซิร์ฟเวอร์)

### 9.2 อะไรต้องเปลี่ยนหรือสร้างใหม่
- **แกนของโดเมน** (ที่ไม่ได้อธิบายในเอกสารนี้): แทน "ยื่นขอ + ตรวจสิทธิ์ + ใบสมัคร + Pass + ตรวจสถานะ + ค่าธรรมเนียม" ด้วยแกนของระบบท่องเที่ยวใหม่ (เช่น แผนทริป การจอง ตั๋วดิจิทัล สถานะ ราคา) ใช้ **โครง "คำขอ → สถานะที่คุมด้วยเครื่องสถานะ → ประวัติ → เอกสาร → การจ่ายเงิน → แจ้งเตือน"** เหมือนเดิม: ทุกการเปลี่ยนสถานะผ่านฟังก์ชันเดียวที่ตรวจคู่สถานะที่อนุญาต + เขียนประวัติ + เรียก `notifyUser` พร้อม `dedupeKey`
- **การเชื่อมต่อภายนอกของโดเมนใหม่:** เขียน adapter ใหม่ + ตัวจำลอง + `outbox` ที่ส่งซ้ำได้ (retry) + `poll` สำรอง ตามแบบเดิม
- **เนื้อหา:** กฎหมาย/ข้อกำหนด/นโยบาย (ให้ที่ปรึกษากฎหมายตรวจ), ภาพประกอบ, ข้อความทุกภาษา

### 9.3 ลำดับสร้างที่แนะนำ (ให้มีของใช้ได้เร็วและลดความเสี่ยง)
1. **สัปดาห์ที่ 1 — ฐาน:** สร้างโปรเจกต์ Next.js + Supabase + Vercel, คัดลอกโทเค็น/เปลือกแอป/เมนู/ปุ่ม/ActionForm/i18n, ล็อกอิน, สิทธิ์เจ้าหน้าที่, `platform_settings`, feature flags, CI + lint:colors + axe
2. **หน้าสาธารณะแบบไม่ต้องล็อกอิน:** FAQ, ข่าว, บทความ, ช่องทางทางการ, กฎหมาย (ได้ SEO และเนื้อหาไว้ก่อน)
3. **แกนของโดเมนใหม่** พร้อมตัวจำลองและเครื่องสถานะ + การจ่ายเงิน (ถ้าจำเป็น)
4. **แจ้งเตือน:** ในแอป → อีเมล → Push → LINE (WhatsApp ทีหลัง เพราะต้องรอ Meta อนุมัติ template)
5. **หลังบ้าน:** คอนโซลคิว, รายได้, กระทบยอด, ตั้งค่า, บันทึกตรวจสอบ
6. **ผู้ช่วย AI** (เริ่มจากงบต่ำ + rate limit + ตัวจำลอง)
7. **ชุดเครื่องมือระหว่างเดินทางของจุดหมายใหม่** + ตัวช่วยฟรีที่ดึงผู้ใช้เข้ามา
8. **เอเจนซี่/พาร์ทเนอร์** เมื่อมีสินค้า/ตัวแทนจริง
9. **งานก่อนเปิดจริง:** PDPA review, UAT, pen-test, load test, ซ้อม backup/restore, ทดสอบ screen reader และอุปกรณ์จริง

| ผู้ช่วย AI ที่อ่านข้อมูลของระบบเอง | ผู้ช่วยวางแผนที่ใช้ข้อมูลที่ยืนยันแล้วของระบบ (ไม่เดา, อ้างอิง, ปฏิเสธนอกขอบเขต) |
| ข่าว + บทความ + SEO หลายภาษา | คอนเทนต์ท่องเที่ยวที่ดึงทราฟฟิกจากการค้นหา |
| Stay Guard (นับวัน + เตือน 7/3/1) | ตัวนับสิทธิ์/กำหนดการ (วีซ่า ตั๋ว ที่พัก เช็กเอาต์) พร้อมเตือน |

### 9.5 บทเรียนและจุดควรระวังที่เจอจริง (อย่าพลาดซ้ำ)
1. **คลาสซ้อนทับของ Tailwind:** `block` ทับ `display` ของ `line-clamp-*` → ข้อความไม่ถูกตัด (ใช้ line-clamp เดี่ยว ๆ)
2. **Realtime ต้องตั้ง auth ก่อน subscribe** (`accessToken` + `await realtime.setAuth(token)`)
3. **งานตามเวลาต้อง compare-and-set** บนแถวเดียวกัน ไม่ใช่ตรวจแค่เวลา ไม่งั้นอีเมลซ้ำเมื่อรันพร้อมกัน
4. **ห้ามแคชหน้าที่มีข้อมูลผู้ใช้ใน service worker**
5. **ลิงก์ออกนอกแอป** (`tel:`, LINE) ไม่ต้องมี spinner; ลิงก์ในแอปต้องมี
6. **เปลี่ยนคีย์เข้ารหัสไม่ได้** หลังมีข้อมูลจริง (วางแผนหมุนคีย์ตั้งแต่ต้นถ้าต้องการ เช่น เก็บรหัสเวอร์ชันคีย์ในข้อมูล)
7. **แหล่งข้อมูลสาธารณะเปลี่ยน/ล่มได้:** ตรวจช่วงค่า อายุข้อมูล และบอกผู้ใช้ว่าเป็นค่าประมาณเมื่อไม่ใช่ค่าวัดจริง; มีแผนสำรอง (เช่นแหล่งฟรีโดนจำกัดโควต้า)
8. **WhatsApp ต้องใช้ template ที่ Meta อนุมัติ** (หลายภาษา = หลาย template) เริ่มขออนุมัติแต่เนิ่น ๆ
9. **ข้อความกฎหมาย/สุขภาพ/ความปลอดภัยต้องให้ผู้เชี่ยวชาญตรวจ** และติดวันที่ตรวจทานล่าสุด; ข้อมูลที่ยังไม่ยืนยันต้องบอกตรง ๆ ไม่เขียนว่าเป็นทางการ
10. **ทดสอบบนมือถือจริง** (ออฟไลน์, Push, PNG, ตำแหน่ง) — สภาพแวดล้อมจำลองตรวจแทนไม่ได้
11. **ห้ามสร้างข้อมูลทดสอบในตารางที่ผู้ใช้จริงเห็น** (เช่น ข่าว) ถ้าสคริปต์เบราว์เซอร์สร้างต้องลบในบล็อก `finally` และยืนยันว่าลบจริง
12. **สีและคอนทราสต์:** สีอ่อนบนพื้นขาว (เช่น ชมพู lotus ตัวอักษรขาว) ตกเกณฑ์ AA; ใช้ `danger` กับป้ายตัวเลข
13. **อย่าให้ UI ที่ซ่อนเมนูเป็นการควบคุมสิทธิ์** ตรวจสิทธิ์ที่หน้าและ action ทุกครั้ง
