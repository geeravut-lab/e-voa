## 1. แนวคิดและเหตุผล

- ผู้ยื่นขอ e-VOA เป็นนักท่องเที่ยวต่างชาติ — หลังได้ Pass แล้วยังต้อง "อยู่ถูกกฎหมายและปลอดภัย" ตลอดทริป เมนูนี้ต่อยอดจากระบบหลักเป็น **ชุดเครื่องมือเล็กๆ ที่ใช้ได้ทันทีโดยไม่ต้องล็อกอิน** (ยกเว้นส่วนที่ต้องมีข้อมูลของผู้ใช้: ทริปใน Stay Guard, เช็กอินครอบครัว, ติดตามพื้นที่)
- หลักผลิตภัณฑ์: **ไม่ทำสิ่งที่แอปท่องเที่ยวทั่วไปมีแล้ว** (จองโรงแรม/ตั๋ว/ทัวร์) แต่ทำสิ่งที่ (1) เกี่ยวกับการเข้า-อยู่ในไทยอย่างถูกกฎหมายและปลอดภัย (2) ใช้ได้ทั้งตอนเครียด/ไม่มีสัญญาณ (3) เป็นหลายภาษา (4) เป็นกลางต่อความรับผิด — เราเป็นเอกชน ไม่ใช่หน่วยงานรัฐ
- รูปแบบหน้าจอ: หน้ารวมเป็นกริดการ์ด (2 คอลัมน์บนจอกว้าง) แต่ละเครื่องมือเป็นหน้าเดี่ยว อ่านง่าย ปุ่มโทรใหญ่ ข้อความสั้น ไม่มีของตกแต่งเกินจำเป็น

## 2. หลักการออกแบบ

1. **ทุกเครื่องมือเปิดได้โดยไม่ล็อกอิน** (SEO + ใช้ได้ในสถานการณ์ฉุกเฉิน) — ส่วนที่ต้องมีบัญชีแสดงปุ่ม "เข้าสู่ระบบ" แทนที่จะซ่อน
2. **เนื้อหาหลักอยู่ในโค้ดเป็นค่าสำรอง (fallback) + แอดมินแก้ทับได้** — การตั้งค่าอ่านไม่ได้/เสียหาย → ใช้ค่าในโค้ด หน้าไม่พัง (กฎ fail-open)
3. **ทุกหน้ามีวันที่ตรวจทานล่าสุดและลิงก์ไปช่องทางทางการ** — เนื้อหากฎหมาย/เบอร์/ค่าธรรมเนียมเปลี่ยนได้ ต้องบอกผู้อ่านตรงๆ
4. **ฟังก์ชันตัดสินใจเป็นฟังก์ชันบริสุทธิ์** (`advise`, `airLevel`, `stayEnd`, `nextStep`, `pickStation`, `warningsFor`, `parseToolkit`) → ทดสอบง่าย ใช้ร่วมกันระหว่างหน้า ผู้ช่วย AI และงานเบื้องหลัง
5. **ไม่เดา**: แหล่งข้อมูลสด (อากาศ/ฝุ่น/คำเตือน) ใช้ไม่ได้ → บอกว่า "ยังไม่มีข้อมูลสด" ไม่แสดงตัวเลขเดา ทุกค่าตรวจช่วงสมเหตุผล (range-check) ก่อนแสดง
6. **ข้อมูลอ่อนไหวอยู่ที่เครื่องผู้ใช้** (ตำแหน่ง, รูปเช่ารถ, ตู้เอกสาร, บัตรสุขภาพ) — เซิร์ฟเวอร์ไม่เห็น ไม่เก็บ
7. **ตำแหน่งไม่เคยถูกส่งเพื่อเลือกข้อมูล**: ผู้ใช้เลือกสถานที่จากรายการที่เรากำหนด (หรือให้มือถือหาสถานที่ใกล้สุด *ในเบราว์เซอร์*) แล้วเซิร์ฟเวอร์ถามด้วยพิกัดของสถานที่นั้น
8. **เหตุการณ์แจ้งเตือนครั้งเดียวต่อเหตุ**: ใช้ `dedupeKey` และ compare-and-set ใน DB ทุกงานเบื้องหลัง — รันซ้ำทุก 10–30 นาทีก็ไม่ส่งซ้ำ
9. **ตัวส่งแจ้งเตือนตัวเดียว** (`notifyUser`) ทุกช่องทาง (ในแอป/Push/LINE/อีเมล) — คำเตือนที่เร่งด่วนปิดอีเมล (`mail:false`)
10. **หน้าที่ต้องเปิดตอนไม่มีเน็ตเป็น HTML ล้วนที่สร้างจากเซิร์ฟเวอร์** (เบอร์ฉุกเฉิน, ตู้เอกสาร) — ไม่มีข้อมูลส่วนตัวในไฟล์, service worker เก็บสำเนา
11. **ลิงก์ลับของผู้ติดต่อเก็บเป็น hash** (256 บิต, `noindex`, `no-referrer`) และหมดอายุเมื่อทริปจบ + 7 วัน
12. **ทุกปุ่ม/ลิงก์มีสปินเนอร์** (`AsyncButton` / `SubmitButton` / `AppLink` / `NavRowLink` / `OutLink`) และข้อความผ่านพจนานุกรม — กฎของโครงการ
13. **สิ่งที่ผู้ใช้กดพลาดแล้วเสียหาย ต้องยืนยันสองชั้น** (ปุ่ม "ต้องการความช่วยเหลือ" เปิดกล่องยืนยันก่อน)
14. **ประเมินจากข้อมูลของผู้ใช้ต้องบอกว่า "ประมาณ"**: Stay Guard คำนวณจากวันถึงที่แจ้งไว้ — ตราประทับของเจ้าหน้าที่เท่านั้นที่เป็นของจริง

## 3. หน้ารวม `/toolkit`: เมนู การนำทาง Back และการไฮไลต์

- **ที่มาของเมนู**: `src/config/nav.ts` แหล่งเดียว — `{ key: "toolkit", label: "card_toolkit", sub: "card_toolkit_sub", href: "/toolkit", icon: "map", art: "toolkit", tone: "mint", size: "half", area: "traveler", auth: false, home: true, side: true }` → ปรากฏทั้งการ์ดหน้าแรก แถบข้าง และ More sheet อัตโนมัติ; ฝั่งแอดมินมีคู่ `toolkit_admin` (`cap: "content"`) ไป `/admin/toolkit`
- **ชื่อเมนู 9 ภาษา** (`card_toolkit`): EN "While in Thailand" · TH "ระหว่างอยู่ไทย" · ZH, HI, AR, RU, KO, JA, ZH-TW มีครบ; คำบรรยาย "วันพำนัก, TDAC, กฎ และวลี"
- **หน้า `/toolkit`**: Server component ไม่ดึงข้อมูล (รายการเครื่องมือเป็นอาเรย์ในหน้า) `PageHead` + `<ul class="grid gap-3 sm:grid-cols-2">` ของ `NavRowLink` (มีสปินเนอร์ตอนนำทาง) การ์ดละสีโทน (`tone-sky/mint/rose/gold/sand`) สลับให้การ์ดข้างเคียงไม่ซ้ำสี, `min-h-24` ให้แตะง่าย; ชื่อ `font-display text-lg`, คำบรรยายสีจาง; metadata ผ่าน `pageMeta` (SEO)
- **ลำดับการ์ด** (ตั้งใจ): ข้อมูลที่ใช้บ่อย/อ่านก่อนเดินทางมาก่อน (อากาศ, Stay Guard, TDAC, เช็กกฎ) → ความปลอดภัย (เมื่อเกิดเหตุ, เช่ารถ, ครอบครัว, ตู้เอกสาร) → ของใช้ตอนฉุกเฉิน (วลี, เบอร์ฉุกเฉิน) — เบอร์ฉุกเฉินเข้าถึงได้ทั้งจากที่นี่และการ์ดหน้าแรกของตัวเอง
- **Back / ไฮไลต์เมนู — สิ่งที่โค้ดเป็นจริง**:
  - `/toolkit` และ `/emergency` อยู่ในตาราง `PARENTS` ระดับบน → ลิงก์ "กลับไปหน้าแรก"
  - การไฮไลต์เมนูข้าง/ล่างใช้ `isActive(path, entry)` กับ `match: [href, /soon/<key>]` (เทียบ path เท่ากันหรือขึ้นต้นด้วย `href + "/"`)
  - ⚠️ **หน้าย่อยอื่นของเมนูนี้ (`/stay`, `/tdac`, `/check-rules`, `/phrases`, `/rental`, `/conditions`, `/family`, `/incident`) ไม่ได้ขึ้นต้นด้วย `/toolkit/` และไม่อยู่ใน `PARENTS`** → (1) เมนู "ระหว่างอยู่ไทย" **ไม่ถูกไฮไลต์** เมื่ออยู่ในหน้าเหล่านั้น (2) **ไม่มีลิงก์ "กลับ" อัตโนมัติ** ไปหน้ารวม (มีเฉพาะปุ่มกลับในหน้าเอง เช่น `/incident/<slug>` → `/incident`, `/family` มีลิงก์ท้ายหน้าไป `/toolkit`) — ดู §14: ควรเพิ่มรายการใน `PARENTS` และรายชื่อ path เพิ่มใน `match` ของเมนู
  - **แนะนำสำหรับโครงการใหม่**: ตั้ง URL ของเครื่องมือย่อยใต้ prefix เดียวกัน (`/toolkit/stay`) หรือให้แต่ละรายการเมนูมี `match` หลาย path และเพิ่ม regex ใน `PARENTS` ตั้งแต่แรก

## 4. โมเดลเนื้อหา

### 4.1 ค่าในโค้ด (`toolkit.ts`, `incidents.ts`, `rental.ts`)
- `PerLang<T>` = `{ en, th, "zh-CN" } + ภาษาเสริมที่เลือกได้` อ่านด้วย `forLang(map, lang)` (ภาษาที่ไม่มี → อังกฤษ)
- ข้อมูล: `EMERGENCY` (เบอร์ + ชื่อ + คำอธิบายการใช้), `PHRASES` (ไทย/คำอ่านโรมัน/ความหมาย en,zh + `more` 6 ภาษา + `urgent`), `RULES_CHECK` (id, `level` ∈ illegal/restricted/respect/careful, title, text), `TDAC` (intro/steps/warn/note), `STAY` (intro/how/extend/overstay/stamp), `INCIDENTS` (id=slug, `call[]`, title, summary, steps[]), `RENTAL` (กลุ่ม→ข้อ) + `PHOTO_SLOTS`
- `LAST_REVIEWED = "2026-11"` ใช้แสดง "ตรวจทานล่าสุด {when}" — **ต้องอัปเดตทุกครั้งที่คนตรวจเนื้อหา**
- ภาษาเสริม 6 ภาษา (HI AR RU KO JA ZH-TW) ใส่ผ่านแพ็ก `content/lang/<code>-a.ts` (เครื่องมือ + เช่ารถ + คำแนะนำอากาศ) และ `-b.ts` (เมื่อเกิดเหตุ + เช็กอินครอบครัว) ด้วยคีย์ id ของสิ่งที่แปล → ไม่ต้องคัดลอกอังกฤษซ้ำ; ตอนโหลดโมดูลจะ "ฉีด" คำแปลเข้า `PerLang` ของรายการในโค้ด

### 4.2 แก้ได้จากหลังบ้าน (`toolkit-store.ts` + `toolkit-server.ts`)
- เก็บใน `platform_settings` คีย์ `toolkit_content` = `{ emergency?, phrases?, rules?, incidents?, reviewed: { <kind>: "YYYY-MM-DD" } }`
- `parseToolkit(raw)` ทำความสะอาดทุกรายการ: ตัดเว้นวรรค/ตัดความยาว/ตรวจรูปแบบ (เบอร์ `^\d{3,6}$` ไม่ซ้ำ, วลีต้องมีอักษรไทย, กฎต้องมี level ถูกต้อง, เหตุการณ์ต้องมี ≥1 ขั้นตอนอังกฤษ) — **รายการเสียถูกทิ้ง ไม่ throw**; รายการที่ว่างทั้งลิสต์ = "ยังไม่ได้แก้" → ใช้ลิสต์ในโค้ด
- `mergeToolkit(stored)` = ลิสต์ที่แก้ ?? ลิสต์ในโค้ด (แยกตามชนิด — แก้เบอร์ฉุกเฉินไม่กระทบวลี)
- `loadToolkit()` เรียก `getSetting` ใน try/catch → ล้มก็คืนค่าในโค้ด + `edited[kind]` + `reviewed[kind]` (วันที่ตรวจทานที่แอดมินกดบันทึก)
- **`carryExtras`**: ฟอร์มหลังบ้านแก้ได้แค่ EN/TH/ZH — รายการในโค้ดที่แอดมิน *ไม่ได้เปลี่ยน* (จับคู่ด้วยเบอร์/th/ข้อความอังกฤษ) จะ "ถือ" คำแปล 6 ภาษาเดิมต่อไป; ถ้าแก้ข้อความ ภาษาเสริมจะแสดงอังกฤษจนกว่าจะมีคำแปลใหม่ในโค้ด
- ขีดจำกัด (`LIMITS`): เบอร์ 12 · วลี 40 · กฎ 30 · เหตุการณ์ 16 · ขั้นตอน 12 บรรทัด×300 ตัวอักษร · ชื่อ 80/100 · ข้อความกฎ 700

## 5. เครื่องมือทีละตัว

### 5.1 เบอร์ฉุกเฉิน `/emergency` (+ แชร์ตำแหน่ง + หน้าออฟไลน์)
- รายการ 6 เบอร์ (1155 ตำรวจท่องเที่ยว, 191, 1669, 199, 1672 ททท., 1178 ตม.) การ์ดละเบอร์: ชื่อ + วิธีใช้ + **ปุ่ม `tel:` เต็มความกว้าง** (สีแดง `danger` สำหรับ 1669/191/1155 อื่นๆ สี primary; ตัวเลข `tabular`) + ข้อความสีเหลืองเตือนว่า "เบอร์อาจเปลี่ยน ลอง 191/1155 ถ้าสายไม่ติด"
- **`LocationBox` (client)**: ปุ่ม `AsyncButton` ขอ `navigator.geolocation` (high accuracy, timeout 20 วินาที) → แสดงพิกัด 6 ตำแหน่งทศนิยม + ± เมตร + ปุ่มคัดลอก + ลิงก์แผนที่ภายนอก (`rel="noopener noreferrer"`) — **ไม่ส่งไปเซิร์ฟเวอร์ ไม่เก็บ**; ถูกปฏิเสธ/ไม่รองรับ → ข้อความอธิบายใน `aria-live`
- ส่วน "วลีด่วน": `PhraseCard` เฉพาะวลี `urgent` + ลิงก์ไป `/phrases`; ปุ่ม "เปิดสำเนาออฟไลน์" `/offline-emergency.html`; ลิงก์ "ช่องทางทางการ"
- **หน้าออฟไลน์ `/offline-emergency.html`** (route handler สร้างจากลิสต์ปัจจุบัน): HTML+CSS ล้วน **ไม่มีสคริปต์ ไม่มีข้อมูลส่วนตัว** แสดงเบอร์ + ปุ่มโทร + 8 วลีด่วน; ค่าข้อความของแอดมิน escape ด้วย `esc()` (`&#<code>;`) กัน HTML injection; `Cache-Control: no-cache`, `X-Robots-Tag: noindex`; service worker เก็บสำเนา (ดู §7)
- เทสต์: ตรวจว่าเบอร์ในหน้าออฟไลน์ตรงกับลิสต์, ทุกเบอร์มีลิงก์ `tel:`, ไม่มี `<script>`, escape ถูก, `sw.js` อ้างถึงหน้านี้

### 5.2 วลีภาษาไทย `/phrases` — `PhraseCard`
- รายการ 2 คอลัมน์: ความหมายในภาษาผู้ใช้ + คำอ่านโรมัน (ซ้าย) และ **ภาษาไทยตัวใหญ่** (ขวา, `lang="th"`) แยกวลี "ด่วน"/"ประจำวัน"
- **แตะวลี → กล่องเต็มจอ** (`role="dialog" aria-modal`, พื้นเข้ม ตัวหนังสือขาว ตัวไทยใหญ่ `text-5xl/7xl`) ให้เจ้าหน้าที่/คนขับอ่าน; ปุ่มปิดได้ `autoFocus`
- ความหมายเลือกตามภาษา: `en` / `zh` / `more[lang]` (6 ภาษาเสริม) สำรองเป็นอังกฤษ
- ข้อสังเกต (§14): กล่องเต็มจอมีโฟกัสอัตโนมัติที่ปุ่มปิด แต่ **ยังไม่มีการกด Esc ปิด และไม่มี focus trap**

### 5.3 เช็กกฎ `/check-rules`
- รายการ 12 เรื่องที่นักท่องเที่ยวมักพลาด (บุหรี่ไฟฟ้า, ยาเสพติดและพัสดุของคนแปลกหน้า, กัญชา, เวลาขายแอลกอฮอล์, สูบบุหรี่ชายหาด, โดรน, สถาบันพระมหากษัตริย์, วัด, ถ่ายภาพ, ขับขี่, เช่า-มัดจำ, เงินสดที่ด่าน ฯลฯ)

### 5.6 Stay Guard `/stay` — นับวันพำนัก
- ล็อกอินแล้ว: ดึงใบสมัครสถานะ `approved`/`used` ของผู้ใช้ + วันถึง (`trips.arrival_date`) + ชื่อผู้เดินทาง (ผ่าน Supabase client ที่มี RLS) → คำนวณ `stayEnd(arrival, stay_days)` และ `daysLeft(end, now)` แสดง "วันที่เหลือ" สีตามเกณฑ์ (`stayLineFor`: >7 เขียว, 1–7 ทอง, 0 "วันสุดท้าย" แดง, ติดลบ "เกิน N วัน" แดง); ผู้ใช้ที่ยังไม่ล็อกอินเห็นคำเชิญเข้าสู่ระบบ
- **กติกาวัน**: วันถึงนับเป็นวันที่ 1 → พำนัก 15 วันที่ถึงวันที่ 1 สิ้นสุดวันที่ 15 (`stayEnd`); ใช้ **วันที่ไทย (UTC+7)** ทั้งหน้าและงาน; จำนวนวันมาจากการตั้งค่ากฎ `rules.stay_guard.stay_days` (ค่าเริ่มต้น 15, จำกัด 1–90, แอดมินแก้ได้, ปิดได้ด้วย `enabled`)
- **เครื่องคิดเลข** (`StayCalculator`, client, ไม่ส่งข้อมูลไปไหน): กรอกวันเข้า + จำนวนวัน (1–365) → วันสุดท้าย + ข้อความ; วันเข้าในอนาคต → "ยังไม่ถึง อีก N วัน"; ผลใน `aria-live="polite"`
- ข้อความอธิบาย: ประมาณจากวันถึงในใบสมัคร, **ตราประทับของเจ้าหน้าที่คือที่ยึดจริง**, การขอต่อ, โทษ overstay
- **เตือนล่วงหน้า 7/3/1 วัน** (งาน "stay" ใน `lib/rules/service.ts`, รันในงานรายวัน): ค้นใบสมัครที่ `arrival_date` อยู่ในช่วง `[วันนี้−stay_days, วันนี้]` → `stayMark(end, now)` คืน 7/3/1 **เฉพาะวันที่ตรงเป๊ะ** (ถ้างานล้มวันหนึ่ง ไม่ส่งชดเชย) → `notifyUser` ภาษาของเจ้าของ + การ์ด LINE มีเลขอ้างอิง, `dedupeKey = rule:stay:<application>:<mark>`, ลิงก์ `/stay`
- เทสต์ (`rules.test.ts`): `stayEnd` รวมข้ามปี/ข้ามเดือน, จุดเตือน 7/3/1 เท่านั้น, ค่ากฎถูกจำกัดช่วง

### 5.7 TDAC `/tdac` — ตัวช่วยฟรี
- อธิบายว่าบัตรเข้าเมืองดิจิทัล (TDAC) **ฟรี แยกจากวีซ่า e-VOA ไม่ใช่ตัวแทน** ขั้นตอน (กรอกบนเว็บทางการภายในกรอบเวลา เตรียมหนังสือเดินทาง/เที่ยวบิน/ที่พัก เก็บหน้าจอยืนยัน) และ **คำเตือนเว็บปลอมที่เก็บเงิน** (`warn[]`)
- ปุ่ม `OutLink` เปิดเว็บทางการ (`TDAC_URL` เป็น `https` + มีเทสต์ตรวจโฮสต์) แท็บใหม่ พร้อมแสดง URL ให้อ่านได้ (`break-all`) — **ไม่มีการพาไปเว็บของเรา/ไม่รับกรอกแทน**
- ล็อกอินแล้วและมีทริปที่ยังไม่ถึง → กล่อง `role="status"` "กรอกได้ตั้งแต่ {from} ถึง {date}" (`from = arrival − 3 วัน`) จากใบสมัครสถานะในกระบวนการ/อนุมัติ, เลือกวันถึงที่ใกล้สุดในอนาคต (วันนี้ตามเวลาไทย)
- ข้อสังเกตเนื้อหา: ข้อความขั้นตอนบอก "ภายใน 3 วันก่อนถึง (นับวันถึงด้วย)" ขณะที่โค้ดคำนวณ `arrival − 3` — **ควรให้ผู้ตรวจทานยืนยันนิยามวันกับประกาศทางการ** แล้วปรับให้ตรงกันทั้งข้อความและตัวเลข

### 5.8 อากาศและฝุ่น `/conditions` — ที่ปรึกษาความปลอดภัย
**ข้อมูล**
- สถานที่: รายการคงที่ 25 แห่ง (`PLACES`: slug, ชื่อ en/th/zh, พิกัด, aliases) — ค้นด้วย `findPlace` (ปรับตัวพิมพ์/ช่องว่าง, ตรงทั้งคำ, aliases); ไม่มีการรับพิกัดจากผู้ใช้
- **พยากรณ์/UV**: Open-Meteo (`/v1/forecast`: อุณหภูมิ, รู้สึกเหมือน, ความชื้น, ลม/กระโชก, ฝน, weather code, สูงสุดวันนี้, โอกาสฝน, UV) + **คุณภาพอากาศแบบจำลอง** (`/v1/air-quality`: PM2.5, PM10, US AQI, UV)
- **PM2.5 วัดจริง**: Air4Thai (กรมควบคุมมลพิษ) ทั้งประเทศใน JSON เดียว ~130 KB → `pickStation`: สถานีที่ใกล้สุดที่มี PM2.5 ล่าสุด **ไม่เกิน 40 กม. และไม่เก่ากว่า 240 นาที** แทนค่าจำลอง; ค่า `-1` = ไม่มีค่า; ตรวจพิกัดอยู่ในกรอบประเทศ; โดนล่มระหว่างรีเฟรช → ใช้สำเนาดีล่าสุด
- **คำเตือนทางการ**: กรมอุตุฯ (CAP RSS) → ดึงเอกสาร CAP ทีละฉบับ (≤6) → `parseCapAlert` รับเฉพาะ `Actual`, ไม่ใช่ `Cancel`, scope `Public` → `warningsFor(place)` จับคู่ **จังหวัด** (`PROVINCE_TH`) ที่คำเตือนระบุ, ต้อง "มีผลอยู่" (`inForce`, ยอมล่วงหน้า 1 ชม.), เรียงใหม่ก่อน, ซ้ำเหตุ+ระดับเดียวกันแสดงครั้งเดียว, สูงสุด 4; **ข้อความคำเตือนแสดงภาษาไทยตามต้นฉบับ** (`lang="th"`)
- **กัน SSRF**: เซิร์ฟเวอร์ดึงลิงก์ในฟีด จึงรับเฉพาะ `https://www.tmd.go.th/uploads/CAP/<ชื่อ>.xml` (และโดเมนเดียวกับฟีดที่ตั้งเองสำหรับเซิร์ฟเวอร์ทดสอบ, ห้าม `..`)
- **แคช**: ผลต่อสถานที่ 10 นาที, สถานี/คำเตือน 10 นาที เก็บใน `globalThis` (ต่ออินสแตนซ์เซิร์ฟเวอร์ — ไม่ใช่แคชกลางเมื่อรันแบบ serverless); ผลที่ "ใช้ไม่ได้" ไม่ถูกแคช; หน้า `/conditions` จำกัดอัตรา (`limited("conditions", 60, 600)`) → เกินแล้วแสดง "ยังไม่มีข้อมูล" แทนการเรียกต้นทาง
- **ใช้ได้เมื่อ** มีอุณหภูมิ *หรือ* PM2.5 *หรือ* คำเตือน; ไม่งั้น `unavailable` — หน้าแสดงกล่อง `role="alert"` "ตอนนี้ยังไม่มีข้อมูลสด"
- ตัวแปรสภาพแวดล้อม (ชื่อ): `OPEN_METEO_API_KEY` (แผนเสียเงิน → ใช้โดเมน `customer-*`), `OPEN_METEO_URL`, `OPEN_METEO_AQ_URL`, `AIR4THAI_URL` (ตั้ง `off` ปิดได้; ค่าเริ่มต้นเป็น **HTTP** เพราะใบรับรอง HTTPS ของต้นทางไม่สมบูรณ์ ณ 8 พ.ย. 2026 — ดึงจากเซิร์ฟเวอร์และ range-check ทุกค่า), `TMD_CAP_URL` (`off` ปิดได้)
- ⚠️ **ใบอนุญาต Open-Meteo ฟรีสำหรับงานไม่แสวงหากำไร** — ระบบเชิงพาณิชย์ต้องใช้แผนเสียเงิน และต้องใส่เครดิต "Weather data by Open-Meteo.com" ทุกที่ที่แสดง (หน้ามีท้ายหน้า)

- UI: `PlacePicker` (`<select>` สถานที่ + ปุ่ม "ใช้ตำแหน่งของฉัน" ที่หาสถานที่ใกล้สุดจากรายการ **ในเบราว์เซอร์** แล้วนำทางด้วย `?place=<slug>` — พิกัดไม่ถูกส่ง), การ์ด "ตอนนี้" (`<dl>` อุณหภูมิ ความชื้น ลม สูงสุด โอกาสฝน UV), การ์ด "คุณภาพอากาศ" (ค่า PM2.5 + ระดับ + แหล่งที่มา: สถานีชื่อ/ห่างกี่กม./เวลา หรือ "แบบจำลอง"), การ์ดคำแนะนำสีตามระดับ, เวลาอัปเดต, ปุ่ม "ถามผู้ช่วย AI"
- **ผู้ช่วย AI**: เครื่องมือ `get_conditions` ใช้ข้อมูลชุดเดียวกัน คืน JSON สั้นๆ (ไม่มีข้อมูล → บอกให้ตอบว่าไม่มี ห้ามเดา) พร้อมระบุแหล่งที่มา/ข้อจำกัด

**ติดตามพื้นที่ + แจ้งเตือนคำเตือนทางการ (ล็อกอิน)**
- `WatchBox`: ปุ่มเปิด/ปิดการติดตามสถานที่ที่กำลังดู + รายการสถานที่ที่ติดตาม (ลบได้ด้วย ✕ มี `aria-label`) — **สูงสุด 5 แห่ง** (`err_watch_limit`), จำกัดอัตรา 30 ครั้ง/ชม.
- ตาราง `warning_watches (user_id, place_slug) PK` — RLS: ผู้ใช้เห็น/เพิ่ม/ลบได้เฉพาะแถวของตน; slug ต้องตรง `^[a-z-]{2,40}$` และอยู่ในรายการสถานที่
- `runWarningAlerts()`: โหลดคำเตือนปัจจุบัน → ทุกคนที่ติดตามจังหวัดที่มีคำเตือน **ระดับ moderate ขึ้นไป** (`worthAlerting`; ระดับ minor ไม่เด้งโทรศัพท์) → `notifyUser({ kind: "weather.warning", dedupeKey: "tmd:<alertId>:<slug>", mail: false })` ในภาษาของผู้ใช้ (Push/LINE/ในแอป — **ไม่ส่งอีเมล** เพราะเร่งด่วนและหมดอายุเร็ว) → ผู้ใช้เดียวกัน + คำเตือนเดียวกัน = ครั้งเดียว
- ตารางเวลา: Vercel Hobby ตั้งเวลาได้แค่วันละครั้ง จึงมี **GitHub Actions `warnings.yml` ทุก 30 นาที** เรียก `GET /api/cron/tick?only=warnings,safety` พร้อม `Authorization: Bearer <CRON_SECRET>` (เทียบแบบ constant-time; ต้องตั้ง secret `SITE_URL` และ `CRON_SECRET` ในรีโปไม่งั้น workflow ข้ามเงียบๆ)

### 5.9 เช็กอินครอบครัว `/family` ("ฉันปลอดภัย") + หน้าของผู้ติดต่อ `/family/<token>`
**แนวคิด**: นักท่องเที่ยวเลือกญาติ/เพื่อน (≤5 คน, ต้องตอบรับเอง) แล้วกด "ฉันปลอดภัย" หรือ "ต้องการความช่วยเหลือ" และตั้งตารางเช็กอินได้ — ถ้าพลาดเกินเวลาที่กำหนด ระบบแจ้งผู้ติดต่อ
**ข้อมูล** (3 ตาราง, RLS เปิดและ **ไม่มี policy** = เบราว์เซอร์อ่านไม่ได้ ใช้ service role ฝั่งเซิร์ฟเวอร์เท่านั้น): `safety_contacts` (ชื่อ, อีเมล, ภาษา, `token_hash` unique, invited/confirmed/revoked/last_notified) · `safety_checkins` (at, status safe|help, lat/lon `numeric(8,3)` ปัดประมาณ 100 ม. **เก็บเฉพาะตอนกด help และติ๊กแนบตำแหน่ง**) · `safety_schedule` (enabled, interval 6/12/24/48 ชม., grace 1–12 ชม., until_date, next_due_at, reminded_at, alerted_at)
**ลิงก์ลับของผู้ติดต่อ**: `newToken()` = 32 ไบต์สุ่ม base64url (256 บิต) → เก็บ `sha256("family:"+token)`; ลิงก์ส่งทางอีเมลเท่านั้น (ถ้าอีเมลไม่ได้ตั้ง ระบบแสดงลิงก์ให้ผู้เดินทางส่งต่อเอง); ส่งใหม่ = โทเค็นใหม่ ลิงก์เก่าตายทันที; ลิงก์ใช้ได้จนวันสิ้นสุด + **7 วัน** (`linkActive`) เพื่อให้ญาติเห็น "ถึงโดยปลอดภัย"; หน้า `noindex`, `referrer: no-referrer`; จำกัดอัตราการเปิดดู 60/10 นาที และการตอบรับ/ออก 30/10 นาที
**ผู้ติดต่อเห็นอะไร**: ชื่อแรกของผู้เดินทาง, เวลาเช็กอินล่าสุด, สถานะ (ปลอดภัย/ต้องการความช่วยเหลือ), "เลยกำหนดหรือไม่" + ปุ่มโทร 1155/191 — **ไม่เห็นตำแหน่ง** (ตำแหน่งอยู่ในอีเมลแจ้งเหตุเท่านั้น) ตอบรับ/ปฏิเสธ/ออกจากรายการได้เอง ไม่ต้องมีบัญชี
**การกดเช็กอิน** (`checkIn`): บันทึก → ตั้ง `next_due_at = now + interval` และล้าง `reminded_at/alerted_at` → **"help" แจ้งทุกผู้ติดต่อที่ตอบรับทันที** (อีเมลภาษาของผู้ติดต่อ + พิกัด + ลิงก์แผนที่ถ้าแนบ); "safe" แจ้งผู้ติดต่อ *เฉพาะเมื่อก่อนหน้านี้เคยมีการแจ้งเตือนพลาดเช็กอินไปแล้ว* ("กลับมาปลอดภัยแล้ว") — ไม่รบกวนทุกครั้ง
**UX**: ปุ่ม "ปลอดภัย" ใหญ่ (`min-h-16 text-xl`) ปุ่ม "ต้องการความช่วยเหลือ" **เปิดกล่องยืนยัน** (กรอบแดง, ติ๊กแนบตำแหน่ง ซึ่งขอจากเบราว์เซอร์ตอนกดส่ง timeout 12 วินาที) กันกดพลาด; ผลลัพธ์ใน `aria-live`; จำกัดอัตรา "help" 6/ชม. "safe" 60/ชม. เชิญ 10/วัน
**ตารางเวลา — ฟังก์ชันบริสุทธิ์ `nextStep(schedule, now)`**: `remind` เมื่อถึงกำหนดและยังไม่ได้เตือนสำหรับกำหนดนี้ (ภายในช่วง grace) → แจ้งผู้เดินทาง; `alert` เมื่อเลยกำหนด + grace และยังไม่ได้แจ้งผู้ติดต่อ → อีเมลหาผู้ติดต่อทุกคนที่ตอบรับ + แจ้งผู้เดินทางว่าแจ้งใครไปแล้ว; ทั้งสองขั้นใช้ **compare-and-set** (`update … where next_due_at = <due> and (reminded_at is null or < due)` + `.select()` ต้องได้ 1 แถว) → รันถี่แค่ไหนก็ครั้งเดียวต่อกำหนด (พบด้วยเทสต์ live และแก้แล้ว: เคยมี race ส่งซ้ำ)
**กติกาอื่น**: `saveSchedule` — เช็กอินล่าสุดภายในรอบนับเป็นฐาน, เริ่มรอบใหม่เมื่อเปิด/เปลี่ยนความถี่, ปิด = ล้าง due; `until_date` เป็นวันที่ไทย ห้ามย้อนหลังเมื่อเปิดใช้; ผู้ติดต่อซ้ำอีเมลถูกปฏิเสธ; เกิน 5 คนถูกปฏิเสธ
**งานเบื้องหลัง**: งาน `safety` ใน tick (เรียกจาก workflow ทุก 30 นาทีพร้อม `warnings`)
**หลักความเป็นส่วนตัวที่เขียนในหน้า**: ไม่ติดตามตำแหน่งต่อเนื่อง, ตำแหน่งแนบเฉพาะตอนขอความช่วยเหลือและปัดหยาบ, ผู้ติดต่อต้องยินยอม ออกเองได้ทุกเมื่อ

### 5.10 ตู้เอกสารออฟไลน์ + บัตรสุขภาพสองภาษา `/offline-vault.html`
- **ทั้งหมดทำงานในเบราว์เซอร์ ไม่มีบัญชี ไม่มีเซิร์ฟเวอร์เก็บข้อมูล**: เซิร์ฟเวอร์ส่งแค่ "หน้าเปล่า" (HTML เดียว + สคริปต์ในตัว + ข้อความภาษาของผู้ใช้) ข้อมูลที่ผู้ใช้เก็บ (เอกสาร ไฟล์ บัตรสุขภาพ) อยู่ใน **IndexedDB ของเครื่องเอง** และเข้ารหัสทั้งหมด
- **การเข้ารหัส** (`crypto-src.ts`, WebCrypto): รหัสผ่านผู้ใช้ → `PBKDF2-SHA256` 250,000 รอบ + salt สุ่ม 16 ไบต์ → กุญแจ `AES-256-GCM` (ใช้เข้ารหัส/ถอดรหัสเท่านั้น `extractable=false`); **ทุกระเบียนมี IV สุ่ม 12 ไบต์ของตัวเอง**; ตรวจรหัสด้วย "ค่าตรวจ" `vault-ok` ที่เข้ารหัสไว้ (ผิด = ถอดไม่ออก); หน่วงเวลาเมื่อใส่ผิดซ้ำ (`min(จำนวนครั้ง, 8)` วินาที); รหัสผ่านขั้นต่ำ 6 ตัว, ต้องกรอกสองครั้งตอนสร้าง; **ลืมรหัส = เปิดไม่ได้** (ไม่มีการกู้คืน และ **ไม่มีปุ่มรีเซ็ต** ในหน้า — มีแค่ข้อความเตือนตอนสร้างรหัสว่าลืมแล้วกู้ไม่ได้ และรหัสสั้นป้องกันได้แค่การเปิดมือเปล่า)
- **ล็อกอัตโนมัติ**: ไม่มีการใช้งาน 3 นาที, แท็บถูกซ่อนเกิน 2 นาที, `pagehide`; เมื่อล็อกจะเคลียร์กุญแจ/รายการ/`blob URL`/การ์ดเต็มจอ
- **เอกสาร**: เพิ่มชื่อ + ประเภท (หนังสือเดินทาง, e-VOA, ประกัน, ที่พัก, ตั๋ว, อื่นๆ) + หมายเหตุ + ไฟล์ (≤4 MB; รูปถูกย่อเป็น JPEG ≤1800px 0.85) สูงสุด 40 รายการ; ดู/ดาวน์โหลด/ลบ (ยืนยัน) ได้; PDF เปิดแท็บใหม่ได้
- **บัตรสุขภาพ** (`health.ts`): ฟอร์ม (ชื่อ วันเกิด หมู่เลือด การแพ้ โรคประจำตัว ยา ผู้ติดต่อ ≤3 ประกัน) ที่ **ป้ายและตัวเลือกคงที่เป็นอังกฤษ+ไทยคู่กัน** (แพทย์ไทยอ่านได้) ส่วนที่ผู้ใช้พิมพ์แสดงตามที่พิมพ์; `cleanHealth` ทิ้งตัวเลือกที่ไม่รู้จัก ตัดความยาว; กดแล้วแสดง **เต็มจอ** ให้แพทย์/เจ้าหน้าที่อ่าน พร้อมข้อความ "ข้อมูลที่ผู้เดินทางกรอกเอง ไม่ใช่เวชระเบียน"
- **ความปลอดภัยของการสร้างหน้า** (`page.ts`): ข้อความที่ผู้ใช้พิมพ์ใส่ DOM ด้วย `textContent` เท่านั้น (ไม่มี `innerHTML`); config JSON ที่ฝังหน้า escape `<`, `U+2028/2029`; โค้ดสคริปต์ในหน้าไม่มีเครื่องหมาย backtick หรือ `${` (ฝังใน template string ดิบ); ไม่มี CDN/ฟอนต์ภายนอก; `noindex`, `no-referrer`
- **ทดสอบโค้ดตัวเดียวกับที่รันบนมือถือ**: เทสต์โหลดข้อความต้นฉบับ `VAULT_CRYPTO_SRC` ผ่าน `new Function(...)` ใน Node (WebCrypto เหมือนกัน) → ตรวจ round-trip, IV ไม่ซ้ำ, ข้อมูลเข้ารหัสไม่มีข้อความดิบ, รหัสผิด/salt ต่าง/ข้อมูลถูกแก้ = ถอดไม่ได้, ทุกภาษามีข้อความครบ
- ข้อจำกัดที่ต้องบอกผู้ใช้ (อยู่ในข้อความของหน้า): ป้องกันโทรศัพท์หาย/ยืมได้ระดับหนึ่ง ไม่ใช่ตู้เซฟธนาคาร — รหัสสั้นถูกเดาได้ถ้ามีคนคัดลอกที่เก็บข้อมูลของเครื่องออกไป; **ควรทดสอบบนเครื่องจริง** เรื่องที่เบราว์เซอร์มือถือบางชนิดอาจล้างพื้นที่เก็บข้อมูลของเว็บที่ไม่ได้ใช้นาน (ยังไม่ได้ยืนยัน — ดู §14)

## 6. ตัวแก้เนื้อหาหลังบ้าน `/admin/toolkit`
- สิทธิ์: `requireAdminPage("content")` ที่หน้า, `requireAdminAction("content")` บรรทัดแรกของ action (บทบาท `manager` และ `editor`)
- 4 ส่วน: **เบอร์ฉุกเฉิน, วลีไทย, เช็กกฎ, เมื่อเกิดเหตุ** (TDAC, Stay Guard, เช่ารถ ยังแก้ในโค้ดเท่านั้น) — แต่ละส่วนมีฟอร์มของตัวเอง บันทึกเฉพาะส่วนนั้น (ส่วนอื่นไม่ถูกแตะ) และมีปุ่ม "กลับไปใช้ค่าในโปรแกรม" (ลบเฉพาะส่วนนั้นออกจากการตั้งค่า)

- **ฟอร์มแบบแถว**: ชื่อ field รูปแบบ `<kind>.<i>.<field>` ทีละแถว (สูงสุด 60 แถว) เปิดแถวว่างเพิ่มให้ 3 แถว, ช่อง "ลบแถวนี้" ติ๊กเพื่อลบ, แถวว่างทั้งแถวถูกข้าม; ข้อความ 3 ภาษา (EN บังคับ, ไทย/中文 ว่าง = ใช้อังกฤษ); ช่องไทย/จีนมี `lang` ที่ถูกต้อง (ให้ตัวอ่านหน้าจอเลือกเสียง)
- `parseToolkitForm` คืนรหัส `err_toolkit_*` (ว่างทั้งหมด, เกินจำนวน, เบอร์ผิดรูป, วลีไม่มีอักษรไทย, ขั้นตอนไม่ครบ, ข้อมูลไม่ครบ) — **ปฏิเสธทั้งชุดถ้ามีแถวเสียแม้แถวเดียว** (ไม่บันทึกครึ่งๆ กลางๆ)
- บันทึก: รวมกับค่าเดิม (`{...cur, [kind]: list, reviewed: {…, [kind]: วันนี้(ไทย)}}`) → `putSetting` (ตรวจผลเขียน) → audit `content.toolkit_save` (เก็บแค่ชนิดและจำนวนรายการ) / `content.toolkit_reset`

## 7. กลยุทธ์ออฟไลน์/PWA (`public/sw.js`)
- Service worker **เก็บเฉพาะ**: `/offline.html`, `/offline-emergency.html`, `/offline-vault.html`, ไอคอน — **หน้าที่มีข้อมูลผู้ใช้ไม่ถูกแคชเลย**
- หน้าเบอร์ฉุกเฉิน/ตู้เอกสาร: *stale-while-revalidate* — ตอบจากสำเนาในเครื่องทันที (เปิดได้ไม่มีเน็ต) แล้วดึงตัวใหม่ในเบื้องหลังเมื่อออนไลน์ (เบอร์ที่แอดมินแก้จึงถึงเครื่องลูกค้าเอง); การนำทางอื่นออฟไลน์ → `offline.html`
- เปลี่ยนรายการแคชทีไร **ต้องเพิ่มเวอร์ชันชื่อแคช** (`evoa-offline-v4`) ไม่งั้นเครื่องเก่าไม่อัปเดต
- ข้อสังเกต: หน้าตู้เอกสารถูกสร้างตามภาษาปัจจุบัน (`getLang()`) แล้วแคชหนึ่งสำเนา — ผู้ใช้ที่เปลี่ยนภาษาจะได้ภาษาใหม่หลังออนไลน์ครั้งถัดไป

## 8. งานเบื้องหลังและการตั้งเวลา
| งาน | ทำอะไร | ความถี่จริง | ป้องกันซ้ำ |

## 10. ถ้อยคำเชิงความรับผิด (ใช้ซ้ำได้ทุกโดเมนที่ให้คำแนะนำ)
- ทุกหน้าที่ให้คำแนะนำมี **กล่องข้อความสีทองท้ายหน้า**: "คำแนะนำทั่วไปจากแหล่งสาธารณะ ตรวจทานล่าสุด {when}; กฎหมาย/ค่าธรรมเนียม/เวลา/เบอร์อาจเปลี่ยน; เจ้าหน้าที่ตัดสินเป็นรายกรณี; ไม่ใช่คำแนะนำทางกฎหมาย; ตรวจที่ช่องทางทางการ" + ปุ่มไป "ช่องทางทางการ"
- ข้อมูลจากต้นทางภายนอกระบุแหล่ง (Open-Meteo, Air4Thai, กรมอุตุฯ) และ **แยกชัดว่าอะไรเป็นค่าวัด/ค่าจำลอง/ทางการ**
- ถ้อยคำ "ประมาณ" ใน Stay Guard, "ไม่ใช่เวชระเบียน" ในบัตรสุขภาพ, "ต้องไม่ฝากพาสปอร์ตเป็นมัดจำ" ในเช่ารถ — เป็นการให้คำแนะนำที่ปกป้องผู้ใช้โดยไม่รับประกันผล
- เรื่องที่ต้องให้ **ผู้รู้ตรวจ** ก่อนเปิดจริง: กฎหมาย/ค่าปรับ/โทษ, ขั้นตอนแต่ละสถานการณ์, คำแปลภาษาอื่น, ข้อความสุขภาพ — เอกสารสถานะของโครงการระบุว่ายังรอการตรวจ

## 11. หลายภาษา
- ข้อความ UI ทั้งหมดผ่านพจนานุกรม 9 ภาษา (`tk_*`, `rc_*`, `inc_*`, `rental_*`, `stay_*`, `tdac_*`, `cond_*`, `emergency_*`, `phrases_*`, ข้อความเช็กอิน `famText`, ข้อความตู้เอกสาร `vaultText` + `text-more`) และ **เนื้อหายาว** (กฎ/เหตุการณ์/เช่ารถ/คำแนะนำอากาศ/เช็กอิน) อยู่ใน `PerLang` + แพ็กภาษาเสริม
- ภาษาอาหรับ (RTL): ใช้ `ps-/pe-/ms-`, `rtl:rotate-180` กับลูกศร, `dir` ของหน้าตู้เอกสารมาจาก `LANGS[lang].dir`
- **อีเมลถึงผู้ติดต่อ** และ **แจ้งเตือนถึงผู้ใช้** ใช้ภาษาของผู้รับ (ผู้ติดต่อเลือกภาษาตอนเชิญ — ตัวเลือกในฟอร์มปัจจุบัน EN/TH/ZH)
- ข้อความของ **คำเตือนกรมอุตุฯ แสดงภาษาไทยตามต้นฉบับ** (ไม่แปล) พร้อมข้อความอธิบายหัวข้อเป็นภาษาผู้ใช้

## 13. กับดักที่เจอจริง
1. **Open-Meteo ฟรีมีโควตาต่อ IP (เคยโดน 429)** และไม่อนุญาตเชิงพาณิชย์ → แคชต่อสถานที่ + จำกัดอัตราหน้า + แผนเสียเงินก่อนเปิดจริง
2. **Air4Thai ใบรับรอง HTTPS ไม่สมบูรณ์** → ดึงผ่าน HTTP ด้วยเซิร์ฟเวอร์ + ตรวจช่วงทุกค่า + ปิดได้ด้วยตัวแปร
3. ค่าขาดเป็น `"-1"` (สตริง) ไม่ใช่ `null` → ต้องแปลงเป็นไม่มีค่า มิฉะนั้นแสดง PM2.5 ติดลบ
4. ฟีดคำเตือนมีหลายฉบับของเหตุเดียวกัน (อัปเดตซ้ำ) → รวมด้วย `event|severity`
5. งานแจ้งเตือนรันซ้ำ → ส่งซ้ำ ถ้าไม่ใช้ dedupeKey/compare-and-set ตั้งแต่แรก
6. Vercel Hobby cron วันละครั้งเท่านั้น → ต้องมีตัวตั้งเวลาภายนอก (GitHub Actions) สำหรับงานเร่งด่วน
7. บัตรเต็มจอ/กล่อง dialog ที่ไม่มี Esc และ focus trap เป็นปัญหา a11y — วางแผนทำตั้งแต่ต้น
8. การเติมคำแปลให้ทุกภาษาหลังเพิ่มฟีเจอร์ใช้เวลา → ออกแบบ `PerLang` ให้ภาษาเสริม "เป็นทางเลือก" แล้วค่อยเติมทีหลังได้
9. การเปลี่ยนไฟล์ที่ service worker เก็บ ต้องเปลี่ยนเวอร์ชันแคช
10. ลบ `blob URL`/กุญแจในหน่วยความจำตอนล็อกหรือออกจากหน้า มิฉะนั้นข้อมูลถอดรหัสแล้วค้างในหน่วยความจำ

### การดัดแปลงไปโดเมนอื่น
- **เปลี่ยนประเทศ/เมือง**: แก้ `PLACES`, `PROVINCE_TH`, ต้นทางคำเตือนและสถานี, เบอร์ฉุกเฉิน, กฎ, เหตุการณ์, วลี (ภาษาท้องถิ่น + คำอ่าน)
- **แอปที่ไม่ใช่การท่องเที่ยว** (เช่น งานภาคสนาม/กิจกรรมกลางแจ้ง/ผู้สูงอายุ): ใช้รูปแบบ "เช็กอิน + ตารางเวลา + ผู้ติดต่อที่ยินยอม", "ตู้เอกสารเข้ารหัสในเครื่อง", "หน้าฉุกเฉิน static ออฟไลน์" และ "ที่ปรึกษาจากข้อมูลสดพร้อมเกณฑ์ชัดเจน" ได้ตรงๆ
- **ขายเป็นโมดูล**: แยกโมดูลเนื้อหา (ข้อมูล + ตัวแก้) ออกจากโมดูลข้อมูลสดและโมดูลแจ้งเตือน เพราะมีความเสี่ยงด้านใบอนุญาต/โควตาต่างกัน
